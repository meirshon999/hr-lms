Часть 1

Как работает

Как работает система. Точные поля и API — в SPEC.md, экраны — в DESIGN.md. Диаграммы — mermaid (рендерятся на GitHub и в предпросмотре Markdown). Готовые картинки — папка diagrams/.

Идея

Онбординг новичка — это линейный проход по урокам, где урок = «материал + тест по нему». Один движок: закрыл урок — открылся следующий. Дошёл до конца — финальный тест-аттестация — статус «завершил».

Четыре решения:

  1. Урок = пара материал + тест. Урок пройден, когда материал засчитан и тест сдан. Тесты без лимита попыток, пересдача сразу — «провала» как состояния нет.
  2. Два гейта открывают онбординг: пройден весь пре-онбординг (материалы о компании) И HR подтвердил кнопкой, что стажировка (офлайн) пройдена. Оба обязательны, порядок между ними не важен.
  3. Снимок траектории. При открытии онбординга структура (блоки, уроки, материалы, тесты, вопросы с ответами) копируется сотруднику. Дальше он учится только по своей копии — правки каталога не могут сломать того, кто уже в пути; они достаются только новым назначениям.
  4. Один сервис, одна БД. Внутри — модули: вход, обучение, управление, конструктор, джобы.

Всё движение сотрудника — это одна машина состояний Employee.stage (intern → onboarding → completed → archived), которую двигают действия HR и прогресс по урокам.

Часть 2

Спецификация

Система онбординга новых сотрудников сети Pingwin Premium. Один сервис. Собрано по требованиям тимлида (интервью 2026-09-07). Логика в схемах — LOGIC.md, экраны и тексты — DESIGN.md.

По этой спецификации собран рабочий прототип — папка prototype/ (TypeScript: Fastify + SQLite на бэке, React + Vite на фронте). Он реализует всё описанное ниже и служит эталоном поведения. Структура кода — под интеграцию в платформу коллеги.

Машиночитаемый контракт API — openapi.yaml в корне проекта (OpenAPI 3.1, все эндпоинты и схемы). Для codegen скармливать его вместе с этим файлом. В прототипе он же отдаётся живым Swagger UI на /docs.

Область v1

Только онбординг новичков. Один новый сотрудник → пре-онбординг → стажировка (офлайн) → онбординг по траектории должности → финальная аттестация → статус «завершил».

Вне v1 (не проектируем): переаттестация действующих, назначение курсов действующим, биометрия/учёт времени, программа механиков боулинга с кайдзен- замерами, филиалы, переводы между должностями, повторный приём как отдельная логика, push-уведомления, массовая загрузка сотрудников списком, отдельные экраны для руководителя подразделения.

Договорённости

  • Один backend-сервис lms + БД. Дробление на микросервисы не делаем.
  • Вход: логин + пароль. Из сессии/токена берём user_id и роль.
  • Идентификаторы — UUID. Даты — YYYY-MM-DD.
  • Часовой пояс компании — Asia/Almaty (настройка TZ). Все «сегодня», даты выхода и дедлайны считаются в нём, а не в UTC: иначе вечером даты съезжают на день.
  • Снимок траектории. При открытии онбординга структура траектории (блоки → уроки → материал + тест + вопросы с ответами) копируется сотруднику. Дальше его обучение идёт только по этой копии: правки каталога не могут сломать того, кто уже учится, и достаются только новым назначениям. Подробно — R-8.
  • Где «⚠️» — решение не подтверждено, см. раздел 11.

1. Роли

Роль Что делает в v1
employee своя траектория: смотрит материалы, проходит тесты. Только своё.
hr заводит сотрудников, ведёт их карточки, отмечает стажировку, архивирует, собирает контент в конструкторе.
admin всё, что hr + заведение учёток, справочник должностей, настройки.
manager ⚠️ роль есть в модели, в v1 без экранов и прав.

Учётку сотрудника создаёт hr/admin вручную при найме (логин + стартовый пароль).

2. Экраны

Сотрудник (мобильный):

  1. Пре-онбординг — список материалов о компании, отметка «Просмотрено». Виден, пока stage = intern. Подпись: онбординг откроется после стажировки.
  2. Моя траектория — список блоков и уроков со статусами, кнопка «Продолжить» на первый незакрытый урок, полоса прогресса. Виден при stage ∈ {onboarding, completed}.
  3. Урок — материал (плеер/просмотрщик) + «Отметить пройденным», затем тест (вопросы по одному, один вариант ответа) + «Завершить тест» + экран результата.
  4. Аттестация — тот же экран теста, большой финальный тест.

HR (компьютер) — «Управление»:

  1. Обзор — сводка: сколько на каждом этапе, просрочено, средний срок онбординга, воронка прохождения блоков по должностям.
  2. Сотрудники — таблица: ФИО, должность, этап, прогресс (N из M уроков), дедлайн, пометка «просрочено». Кнопка «Добавить сотрудника».
  3. Карточка сотрудника — этап, прогресс по блокам и урокам, переключатель «Стажировка пройдена» / «Не прошёл», кнопка «В архив». Блок «Профиль и доступ»: логин, сброс пароля, ссылка-приглашение, правка ФИО/телефона.
  4. Конструктор — должности → траектория должности → материалы пре-онбординга, блоки → уроки (материал + тест), блок аттестации. Порядок элементов ↑↓, «Предпросмотр» (как видит сотрудник), переключатель «Опубликовать».

Тексты, состояния (пусто/загрузка/ошибка), цвета, шрифты — в DESIGN.md.

3. Данные

Учётные

User — всё, что логинится.

  • id, login (uniq), password_hash, role (enum: employee | hr | admin | manager)
  • employee_id (uuid, nullable — заполнен, если role=employee)
  • is_active (bool) — false закрывает вход

Люди

Position (должность)

  • id, name

Employee

  • id, user_id (uniq)
  • full_name (1–160)
  • position_id → Position
  • phone (string, uniq среди всех сотрудников включая архивных) — E.164, не меняется
  • start_date (date) — дата выхода
  • stage (enum: intern | onboarding | completed | archived, default intern)
  • internship_passed (bool, default false) — выставляется кнопкой HR «Стажировка пройдена»
  • pre_onboarding_done (bool, default false)
  • onboarding_opened_at (datetime, nullable)
  • onboarding_due_date (date, nullable) — onboarding_opened_at + config.onboarding_days
  • overdue (bool, default false)
  • completed_at (datetime, nullable)
  • archived_at (datetime, nullable)
  • pre_snapshot_json (text, nullable) — замороженный список id материалов пре-онбординга, снимается при найме (R-8)
  • snapshot_json (text, nullable) — замороженная структура траектории, снимается при открытии онбординга (R-8)
  • индексы: phone uniq, user_id uniq, (position_id, stage)

Контент (траектория должности)

Trajectory — 1:1 с Position.

  • id, position_id (uniq)
  • status (enum: draft | active) — active = готова, по ней открывается онбординг

PreOnboardingItem — материал этапа пре-онбординга.

  • id, trajectory_id, order (int), title
  • content_type (enum: video | pdf | text)
  • file_url (nullable — для video/pdf), text_body (nullable — для text)

Block

  • id, trajectory_id, order (int), title
  • kind (enum: regular | attestation) — ровно один attestation, он последний

Lesson — только в блоках regular.

  • id, block_id, order (int), title

Material — 1:1 с Lesson.

  • id, lesson_id (uniq)
  • content_type (enum: video | pdf | text)
  • file_url (nullable), text_body (nullable)
  • min_watch_pct (int 0–100, nullable — для video; null = засчитывать по «долистал»)

Test — 1:1 с Lesson (обычный урок) ИЛИ 1:1 с Block attestation (финальный).

  • id, lesson_id (nullable), block_id (nullable) — заполнено ровно одно
  • pass_mark_pct (int 0–100) — задаёт автор контента в конструкторе

Question

  • id, test_id, order (int), text
  • options (json: список строк, 2–6)
  • correct_option_index (int) — наружу сотруднику не отдаётся

Прогресс

PreOnboardingView

  • id, employee_id, item_id, viewed_at (datetime). Uniq (employee_id, item_id).

LessonProgress

  • id, employee_id, lesson_id — id урока из снимка (внешнего ключа на живой каталог нет: урок могли удалить)
  • status (enum: locked | available | passed)
  • material_done (bool, default false)
  • video_pct (int 0–100, default 0) — накопленный просмотр видео, растёт только вверх
  • passed_at (datetime, nullable)
  • Uniq (employee_id, lesson_id). Создаётся пачкой при открытии онбординга.

TestAttempt — храним все попытки.

  • id, employee_id, test_id (из снимка), attempt_no (int)
  • answers (json: [{question_id, option_index}])
  • score_pct (int), passed (bool)
  • submitted_at (datetime)

Аудит

AuditLog — постоянный журнал действий HR/админа.

  • id, ts, actor_login, action (hire | internship_passed | internship_failed | archive | edit_profile | reset_password | publish | unpublish), employee_id (nullable), detail (text)
  • Индекс по employee_id. Показывается в карточке сотрудника («История действий»).

4. Жизненный цикл сотрудника

Этапы: intern → onboarding → completed → archived. Плюс жёсткое удаление на проваленной стажировке.

Переход Когда Что делает система
[*] → intern HR/admin заводит сотрудника (≈ за день до start_date) создаёт User + Employee, роль employee, stage=intern. Разворачивает PreOnboardingView-цели по всем PreOnboardingItem траектории.
intern → удалён HR в карточке: «Стажировку не прошёл» удаляет User, Employee и весь его прогресс безвозвратно.
intern → onboarding выполнено всё: pre_onboarding_done = true И internship_passed = true И trajectory.status = active stage=onboarding, onboarding_opened_at=now, onboarding_due_date=now+14д. Создаёт LessonProgress по всем урокам: первый урок первого regular-блока → available, остальные → locked.
onboarding → completed сдан тест блока attestation stage=completed, completed_at=now.
любой активный → archived HR в карточке: «В архив» (⚠️) stage=archived, archived_at=now, user.is_active=false. Прогресс сохраняется.

internship_passed становится true, когда HR нажимает в карточке кнопку «Стажировка пройдена». Автоматического открытия по дням нет — стажировка офлайн, её длительность у каждой роли своя, и подтверждает её наставник/HR вручную. Кнопка «Стажировку не прошёл» — удаляет сотрудника целиком.

pre_onboarding_done становится true, когда число PreOnboardingView у сотрудника = числу PreOnboardingItem в траектории.

Порядок пре-онбординга и стажировки между собой не важен — нужны оба.

5. Логика обучения

R-1. Пре-онбординг

Все PreOnboardingItem траектории доступны сотруднику с момента найма. Открытие элемента (для text — долистал; для video — досмотрел до конца; для pdf — открыл) создаёт PreOnboardingView. Порядок не навязываем.

R-2. Открытие онбординга

См. раздел 4. Пока онбординг не открыт, экран «Моя траектория» недоступен, сотрудник видит только пре-онбординг.

R-3. Прохождение урока

Урок = материал + тест. Урок passed, когда material_done=true И есть TestAttempt с passed=true.

  • Материал засчитан (material_done=true): для text — конец текста попал в экран; для pdf — открыл; для video — сервер проверяет накопленный LessonProgress.video_pct ≥ min_watch_pct. Клиент шлёт прогресс просмотра (POST /me/lessons/{id}/video-progress), решение принимает сервер: иначе «просмотр» подделывается одним запросом. Идемпотентно.
  • Тест: POST ответов → сервер считает score_pct по верным ответам из снимка → passed = score_pct ≥ pass_mark_pct. Попытки не ограничены. Не сдал — проходит заново сразу. Пройденный тест можно перепройти: урок остаётся passed, новая попытка просто записывается.

R-4. Разблокировка следующего урока

После того как урок стал passed: следующий по order урок того же блока → available. Если уроки блока кончились — первый урок следующего regular-блока → available. Всё строго по порядку.

R-5. Финальная аттестация

Блок attestation (тест без уроков) становится доступен, когда все уроки всех regular-блоков = passed. Сдача теста аттестации → stage=completed. Не сдал → проходит заново сразу, без ограничений.

R-6. Просрочка

Ежедневный джоб: если stage=onboarding и onboarding_due_date < today → overdue=true. Ничего не блокируется, сотрудник доучивается. Снимать флаг не нужно (при completed он неважен).

R-7. Один онбординг на сотрудника

У Employee ровно одна траектория (по должности), ровно один набор LessonProgress. Смены должности в v1 нет.

R-8. Снимок траектории (изоляция от правок каталога)

  • При найме замораживается список материалов пре-онбординга (Employee.pre_snapshot_json — массив id). pre_onboarding_done считается по нему, а не по текущему каталогу.
  • При открытии онбординга (R-2) замораживается вся структура траектории (Employee.snapshot_json): блоки, уроки, порядок, материалы, тесты, вопросы вместе с верными ответами. Идентификаторы сохраняются как есть, поэтому LessonProgress и TestAttempt продолжают ссылаться на них.
  • Всё обучение (список уроков, разблокировка, содержимое урока, оценка теста, аттестация, прогресс в карточке HR и воронка) читается из снимка.
  • Живьём из каталога не берётся ничего. Удаление урока, теста или вопросов у active-траектории не влияет на тех, кто уже учится.
  • Новые назначения берут актуальную версию каталога.

6. Конструктор контента (правила)

  • C-1 У каждой должности ровно одна Trajectory. Создаётся вместе с должностью в статусе draft.
  • C-2 draft → active (переключатель «Опубликовать») запрещён, если: нет ни одного regular-блока с уроком; у урока нет материала или нет теста; нет блока attestation с тестом; у теста нет вопросов; у вопроса < 2 вариантов или correct_option_index вне диапазона.
  • C-3 Пока trajectory.status = draft, сотрудники этой должности заводятся, но онбординг им не открывается (ждут; см. раздел 4).
  • C-4 Правка active-траектории разрешена в любой момент и никак не затрагивает тех, кто уже учится — у каждого свой снимок (R-8). Правки достаются только сотрудникам, у которых онбординг откроется после правки. Пересчитывать чужой прогресс не нужно.
  • C-5 Блок attestation всегда последний и всегда ровно один.
  • C-6 Загрузка файлов (видео/pdf) — через хранилище (⚠️ им займётся другая команда; здесь только file_url).
  • C-7 Все действия HR/админа над сотрудниками и публикацией пишутся в AuditLog (кто, что, когда) — см. раздел 3.

7. API (сервис lms, префикс /api/v1)

Формат ошибки: { "error": {"code","message","details?"}, "request_id" }. Коды: 400 валидация, 401 нет сессии, 403 нет прав, 404, 409 конфликт состояния, 422 бизнес-правило.

Вход

  • POST /auth/login — {login, password} → {token, role}.
  • POST /auth/logout.
  • GET /me → {user, employee?, role}.

Сотрудник — обучение

  • GET /me/pre-onboarding → список PreOnboardingItem + отметки просмотра.
  • POST /me/pre-onboarding/{item_id}/view → отметить просмотренным.
  • GET /me/trajectory → блоки → уроки со статусами + progress (N из M) + доступность аттестации. 409, если stage != onboarding/completed.
  • GET /me/lessons/{lesson_id} → материал + тест (вопросы без правильных ответов). 403, если урок locked.
  • POST /me/lessons/{lesson_id}/video-progress — {pct} → накопленный video_pct.
  • POST /me/lessons/{lesson_id}/material-done → material_done=true (идемпотентно). 422 video_not_watched, если видео не досмотрено до min_watch_pct.
  • POST /me/lessons/{lesson_id}/test — {answers:[{question_id, option_index}]} → {score_pct, passed}. Пишет TestAttempt, при passed пересчитывает R-4.
  • GET /me/attestation → тест аттестации. 403, если R-5 не выполнено.
  • POST /me/attestation/test — как урок; при passed → stage=completed.

HR — сотрудники

  • POST /employees — {full_name, position_id, phone, start_date, login, password} → создаёт User+Employee. 422 no_active_trajectory в warnings (не блокирует).
  • GET /employees?position_id&stage&overdue&search&limit&cursor → таблица со сводкой прогресса.
  • GET /employees/{id} → карточка: этап, прогресс по блокам/урокам, пре-онбординг, login.
  • PATCH /employees/{id} — {full_name?, phone?} (проверка уникальности телефона).
  • POST /employees/{id}/internship-passed → internship_passed=true, пробует открыть онбординг.
  • POST /employees/{id}/internship-failed → удаляет сотрудника целиком. 409, если stage != intern.
  • POST /employees/{id}/archive → stage=archived, user.is_active=false.
  • POST /employees/{id}/reset-password → {password} (новый, показывается один раз).
  • POST /employees/{id}/invite → {invite_url, login}.
  • GET /employees/{id}/audit → журнал действий по сотруднику.
  • GET /positions, POST /positions — {name}; PATCH /positions/{id}; DELETE /positions/{id} (только если нет сотрудников).

HR — аналитика

  • GET /audit?limit → общий журнал действий.
  • GET /analytics → {by_stage, total, overdue, avg_onboarding_days, funnel:[{position, cohort, attested, blocks:[{title, passed}]}]}.

HR — конструктор

  • GET /trajectories/{position_id} → полное дерево (с правильными ответами) + problems[].
  • POST /trajectories/{position_id}/pre-onboarding / PATCH /pre-onboarding/{id} / DELETE.
  • PUT /trajectories/{position_id}/pre-onboarding/order — {ids:[...]}.
  • POST /trajectories/{position_id}/blocks / PATCH /blocks/{id} / DELETE.
  • PUT /trajectories/{position_id}/blocks/order — {ids:[...]} (regular; аттестация всегда последняя).
  • POST /blocks/{id}/lessons / PATCH /lessons/{id} / DELETE.
  • PUT /blocks/{id}/lessons/order — {ids:[...]}.
  • PUT /lessons/{id}/material — {content_type, file_url?, text_body?, min_watch_pct?}.
  • PUT /lessons/{id}/test — {pass_mark_pct}; POST /tests/{id}/questions / PATCH / DELETE.
  • PUT /blocks/{attestation_id}/test — тест аттестации.
  • POST /trajectories/{position_id}/publish — draft→active, проверка C-2.
  • POST /trajectories/{position_id}/unpublish — active→draft.

11. Решённые ранее вопросы (зафиксировано)

  1. Названия этапов — рабочие: «Стажировка / Онбординг / Завершил / Архив» (intern/onboarding/completed/archived). Меняются легко.
  2. Увольнение — HR жмёт «В архив» в карточке; архивные скрыты в таблице за галкой «Показать архивных».
  3. Перепрохождение сданного теста — урок остаётся passed при провальной новой попытке (новая попытка просто записывается).
  4. Число вопросов и проходной балл любого теста и аттестации — задаёт автор контента в конструкторе.
  5. Хранилище файлов — отдельная команда; спецификации достаточно file_url.
  6. В конструкторе работают hr и admin.

Всё это реализовано в прототипе (prototype/).

Требуют решения (нашлись при сборке прототипа)

  • Повторный приём сейчас невозможен. phone уникален среди всех, включая архивных, а повторный приём = новый профиль → уволенного с тем же телефоном завести нельзя. Варианты: освобождать телефон при архивации; разрешать дубль, если все прежние держатели в архиве; или HR редактирует старую запись.
  • Нет журнала действий HR — сделано: AuditLog + «История действий» в карточке сотрудника (раздел 3, правило C-7).
  • Онбординг нельзя поставить на паузу (болезнь, отпуск) — дедлайн идёт всегда.
  • Список сотрудников грузится целиком — ок для пилота, для масштаба нужна пагинация (?limit&cursor).

Часть 3

Экраны и тексты

Дизайн интерфейса. Логика — LOGIC.md, данные и API — SPEC.md. Область v1 — онбординг новых сотрудников (см. SPEC.md, раздел «Область v1»).

1. Что это

Единый цифровой путь новичка: пре-онбординг → стажировка → онбординг по траектории должности → финальная аттестация → «онбординг завершён».

  • Сотрудник — телефон. Логин + пароль (выдаёт HR при найме). Смотрит материалы, проходит тесты.
  • HR — компьютер. Заводит сотрудников, ведёт карточки, отмечает стажировку, собирает контент в конструкторе.
  • Админ — то же, что HR, плюс учётки и справочник должностей.
  • Руководитель подразделения — роль есть в системе, но в v1 без экранов.

2. Экраны сотрудника (мобильный, вертикаль)

App-shell. У всех экранов сотрудника одинаковый каркас: компактная липкая шапка (знак/«← Назад», имя экрана, «выйти») → прокручиваемое тело → липкая нижняя панель с одним главным действием (достаётся большим пальцем). Второстепенные действия — в теле. Зона нажатия ≥ 44px, варианты ответа ≥ 56px, базовый текст 16px (иначе iOS зумит поля ввода). Нет сети — сверху красная полоса «Нет сети — изменения не сохранятся». Загрузка — скелетоны, не текст.

Экран 1 — Пре-онбординг

Когда: этап «Стажировка» (stage = intern). Зачем: познакомить с компанией до и во время стажировки.

Элементы:

  • Шапка: «Добро пожаловать в Pingwin, {Имя}».
  • Подпись: «Пока идёт стажировка, изучите материалы о компании. Онбординг откроется, когда HR отметит стажировку пройденной.»
  • Список материалов (о Pingwin, точки и форматы, оргструктура, должностные обязанности, welcome-видео). У каждого: иконка типа, статус «Просмотрено» (золотая галочка) или «Не открыто».
  • Внизу: «Просмотрено {N} из {M}».

Действие: тап по материалу → открывается просмотрщик; после просмотра (видео — до конца, текст — долистал, PDF — открыл) ставится галочка.

Состояния:

Состояние Что видно
Загрузка Скелет списка, подпись «Загружаем материалы…».
Ошибка сети «Не удалось загрузить. Проверьте интернет и нажмите «Повторить».» + «Повторить».
Всё просмотрено Плашка: «Вы изучили все материалы. Дождитесь окончания стажировки — откроется онбординг.»

Экран 2 — Моя траектория

Когда: этапы «Онбординг» и «Завершил». Зачем: видно, где сотрудник и что дальше.

Элементы:

  • Шапка: «{Имя}», ниже мелким — должность.
  • Блок «Ваш следующий шаг»: название урока, иконка (материал/тест), кнопка «Продолжить».
  • Список блоков; под каждым — уроки со статусом: пройден (золотая галочка), доступен, заблокирован (замок). Последним — блок «Аттестация».
  • Внизу: полоса прогресса «Пройдено {N} из {M} уроков», срок «Завершить до {дата}».

Действие: «Продолжить» → первый незакрытый урок (или аттестация).

Состояния:

Состояние Что видно
Загрузка Скелет карточки следующего шага и списка.
Ошибка сети «Не удалось загрузить. Проверьте интернет и нажмите «Повторить».» + «Повторить».
Просрочено Полоса прогресса красная, подпись «Срок прошёл — пройдите оставшиеся шаги как можно скорее.» Доступ сохраняется.
Всё пройдено, аттестация доступна Кнопка «Продолжить» → «Перейти к аттестации».
Онбординг завершён Вместо «Продолжить» — плашка «Онбординг завершён. Молодцы! Все уроки остаются доступны для повторения.»

Экран 3 — Урок

Когда: открыт из «Моей траектории». Зачем: пройти один урок — материал и тест по нему.

Шапка: «← Назад», название урока, «Урок {N} из {M}». Под шапкой — индикатор из двух полосок: урок идёт в два шага, материал → тест (на телефоне без бесконечной простыни).

Тело, шаг 1 — материал:

  • Видео — плеер с полосой прогресса и счётчиком «{N}% · нужно {M}%». PDF — просмотрщик. Текст — обычный поток страницы.
  • Кнопка «Отметить пройденным» в липкой нижней панели. Активна: для видео — накопленный просмотр ≥ заданного % (проверяет сервер; подсказка «Досмотрите видео до {M}%»); для текста — конец текста попал в экран (подсказка «Дочитайте материал до конца»); для PDF — сразу.

Тело, шаг 2 — тест (появляется после «Отметить пройденным»):

  • Вопросы по одному, один вариант ответа, кнопка «Далее»; на последнем — «Завершить тест».
  • Экран результата:
    • сдал: «Тест сдан — {N}%. Следующий шаг открыт.» + «Вернуться к траектории».
    • не сдал: «Тест не сдан — {N}%, нужно {M}%. Попробуйте ещё раз.» + «Пройти заново».

Состояния:

Состояние Что видно
Загрузка «Загружаем урок…», скелет.
Ошибка (материал не грузится) «Материал не загрузился. Проверьте интернет и нажмите «Обновить».» + «Обновить».
Ошибка (ответы не отправились) «Не удалось отправить ответы. Нажмите «Повторить».» + «Повторить».
Урок уже пройден (открыт повторно) Материал и тест доступны для повторения, вверху подпись «Урок пройден».

Экран 4 — Аттестация

Когда: все уроки пройдены, открыт из «Моей траектории». Зачем: финальный тест по всем блокам.

  • Вступление: «Финальная аттестация. {K} вопросов по всем темам онбординга. Проходной балл — {M}%. Попыток не ограничено.» + «Начать».
  • Далее — тот же экран теста, что в уроке.
  • Результат:
    • сдал: «Аттестация пройдена. Онбординг завершён!» + «На главную».
    • не сдал: «Аттестация не пройдена — {N}%, нужно {M}%. Попробуйте ещё раз.» + «Пройти заново».

3. Экраны HR (компьютер; на телефоне — мини-версия)

HR на телефоне: разделы переезжают в верхнюю прокручиваемую полосу, таблица сотрудников превращается в карточки, карточка сотрудника и кнопка «Стажировка пройдена» полностью работают. Конструктор на телефоне не редактируется — показывается подсказка «Конструктор рассчитан на компьютер».

Экран 5 — Сотрудники

  • Таблица: ФИО · Должность · Этап (Стажировка / Онбординг / Завершил / Архив) · Прогресс (полоса + «N из M») · Срок · пометка «Просрочено».
  • Фильтры: должность, этап. Поиск по ФИО. По умолчанию архивные скрыты (галка «Показать архивных»).
  • Кнопка «Добавить сотрудника» → форма: ФИО, должность, телефон, дата выхода, логин, стартовый пароль.
  • Клик по строке → карточка.

Состояния:

Состояние Что видно
Пусто «Здесь появятся сотрудники после добавления.» + «Добавить сотрудника».
Загрузка Скелет таблицы.
Ошибка «Не удалось загрузить список. Обновите страницу.» + «Обновить».
Форма: телефон занят «Сотрудник с таким телефоном уже есть.»
Форма: нет траектории Сотрудник создаётся, плашка «Траектория для должности «{название}» ещё не опубликована — онбординг откроется после публикации.»

Экран 6 — Карточка сотрудника

  • Шапка: ФИО, должность, телефон, дата выхода, этап.
  • Блок «Стажировка» (виден на этапе «Стажировка»): пояснение, что онбординг откроется после кнопки и завершённого пре-онбординга; кнопки «Стажировка пройдена» и «Не прошёл».
  • Блок «Пре-онбординг»: «Просмотрено {N} из {M}».
  • Блок «Онбординг»: список блоков и уроков со статусами, попытки тестов, срок, пометка «Просрочено».
  • Блок «Профиль и доступ»: телефон, логин, кнопки «ссылка-приглашение» и «сбросить пароль» (новый пароль показывается один раз), кнопка «Изменить» (ФИО, телефон).
  • Блок «История действий»: кто и когда завёл, отметил стажировку, сбросил пароль, перевёл в архив.
  • Кнопка «В архив» (с подтверждением).

Тексты подтверждений:

Действие Текст
«Не прошёл» «Удалить сотрудника «{ФИО}»? Аккаунт и весь его прогресс будут удалены безвозвратно.»

Экран 7 — Конструктор

  • Слева: список должностей; у каждой — статус траектории (Черновик / Опубликована).
  • Выбор должности → редактор траектории:
    • Пре-онбординг: список материалов, «Добавить материал» (тип, файл/ссылка/текст).
    • Блоки: список, «Добавить блок», перетаскивание порядка.
    • Урок: «Добавить урок» → материал (тип, файл/текст, для видео — % просмотра)
      • тест (проходной балл, вопросы: текст, 2–6 вариантов, отметка верного).
    • Блок «Аттестация»: один тест (проходной балл, вопросы).
  • Кнопка «Опубликовать» / «Снять с публикации».

Состояния:

Состояние Что видно

Публикация запрещена «Нельзя опубликовать: {список}. Например: «Урок «Меню» — нет теста», «Нет блока аттестации».»

Плейсхолдеры в фигурных скобках подставляются на месте.

7. Правила для сборки

  • Одна библиотека компонентов, цвета только через --color-*.
  • Экраны сотрудника — mobile-first: вертикаль, зона нажатия ≥ 44×44px, кнопки во всю ширину. До контента — не больше двух тапов от «Моей траектории».
  • Экран HR — desktop-first: таблица со своим скроллом, шапка и фильтры зафиксированы, страница по горизонтали не скроллится.
  • Иконки — один линейный набор, не эмодзи.
  • Видео: вертикальные и горизонтальные, адаптивный плеер, прогресс просмотра сохраняется между заходами.
  • У каждого экрана обязательны состояния: пусто, загрузка, ошибка — с текстами из раздела 6.
  • Push-уведомлений в v1 нет — изменения статусов сотрудник видит сам при заходе.
