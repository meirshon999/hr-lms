## Идея

Онбординг новичка — это **линейный проход по урокам**, где урок = «материал + тест
по нему». Один движок: закрыл урок — открылся следующий. Дошёл до конца —
финальный тест-аттестация — статус «завершил».

Четыре решения:

1. **Урок = пара материал + тест.** Урок пройден, когда материал засчитан и тест
   сдан. Тесты без лимита попыток, пересдача сразу — «провала» как состояния нет.
2. **Два гейта открывают онбординг:** пройден весь пре-онбординг (материалы о
   компании) И HR подтвердил кнопкой, что стажировка (офлайн) пройдена.
   Оба обязательны, порядок между ними не важен.
3. **Снимок траектории.** При открытии онбординга структура (блоки, уроки,
   материалы, тесты, вопросы с ответами) копируется сотруднику. Дальше он учится
   только по своей копии — правки каталога не могут сломать того, кто уже в пути;
   они достаются только новым назначениям.
4. **Один сервис, одна БД.** Внутри — модули: вход, обучение, управление,
   конструктор, джобы.

Всё движение сотрудника — это одна машина состояний `Employee.stage`
(`intern → onboarding → completed → archived`), которую двигают действия HR и
прогресс по урокам.

## 3. Машины состояний

### 3.1 Сотрудник — Employee.stage

```mermaid
stateDiagram-v2
    state "стажёр (intern)" as I
    state "онбординг (onboarding)" as O
    state "завершил (completed)" as C
    state "архив (archived)" as A
    state "удалён" as D
    [*] --> I : HR завёл сотрудника, за день до выхода
    I --> D : HR отметил, стажировку не прошёл
    I --> O : пре-онбординг и стажировка пройдены, траектория активна
    O --> C : сдан финальный тест аттестации
    I --> A : HR в архив
    O --> A : HR в архив
    C --> A : HR в архив
    D --> [*]
```

### 3.2 Урок — LessonProgress.status

```mermaid
stateDiagram-v2
    [*] --> locked : создан при открытии онбординга
    locked --> available : предыдущий урок passed, либо это первый урок
    available --> passed : материал засчитан И тест сдан
    passed --> passed : перепрохождение теста, остаётся passed
```

## 4. Найм → стажёр

```mermaid
flowchart TD
    A["HR: Добавить сотрудника — ФИО, должность, телефон, дата выхода, логин, пароль"] --> B{"телефон уникален?"}
    B -->|нет| E["ошибка: телефон занят"]
    B -->|да| C["создать User + Employee, stage = intern"]
    C --> D["развернуть цели пре-онбординга по материалам траектории должности"]
    D --> F{"траектория должности активна?"}
    F -->|да| G["сотрудник видит пре-онбординг; онбординг откроется по двум гейтам"]
    F -->|нет| H["сотрудник видит пре-онбординг; онбординг ждёт публикации траектории"]
```

## 5. Два гейта → открытие онбординга

```mermaid
flowchart TD
    subgraph Gate1["Гейт 1 — пре-онбординг, в приложении"]
      P1["сотрудник открывает материалы о компании"] --> P2{"все материалы просмотрены?"}
      P2 -->|да| P3["pre_onboarding_done = true"]
    end
    subgraph Gate2["Гейт 2 — стажировка, офлайн, у каждой роли свой срок"]
      S2["HR нажал: Стажировка пройдена"] --> S3["internship_passed = true"]
      S4["HR нажал: Не прошёл"] --> S5["сотрудник и весь прогресс удалены"]
    end
    P3 --> G{"pre_onboarding_done И internship_passed И траектория активна?"}
    S3 --> G
    G -->|да| O["снимок траектории зафиксирован; stage = onboarding; дедлайн +14 дней; первый урок available"]
    G -->|нет| W["ждём оставшееся условие"]
```

## 6. Прохождение урока

```mermaid
flowchart TD
    A["сотрудник открыл урок (available)"] --> B["смотрит материал"]
    B --> C{"материал засчитан? долистал текст, открыл pdf, досмотрел видео до нужного процента"}
    C -->|нет| B
    C -->|да| D["material_done = true (для видео процент проверяет сервер)"]
    D --> E["проходит тест урока"]
    E --> F["сервер считает балл по верным ответам"]
    F --> G{"балл не ниже проходного?"}
    G -->|нет| H["не сдан — проходит заново сразу, попыток без лимита"]
    H --> E
    G -->|да| I["урок passed"]
    I --> J["движок разблокировки (раздел 7)"]
```

## 7. Разблокировка и аттестация

```mermaid
flowchart TD
    A["урок стал passed"] --> B{"в этом блоке есть следующий урок?"}
    B -->|да| C["следующий урок → available"]
    B -->|нет| D{"есть следующий regular-блок?"}
    D -->|да| E["первый урок следующего блока → available"]
    D -->|нет| F{"все уроки всех regular-блоков passed?"}
    F -->|да| G["блок аттестации → доступен"]
    F -->|нет| H["ждём"]
    G --> I["сотрудник сдаёт финальный тест по всем блокам"]
    I --> J{"сдан?"}
    J -->|нет| I
    J -->|да| K["stage = completed, статус: онбординг завершён"]
```

Просрочка: если дедлайн (14 дней) прошёл, а онбординг не завершён — у HR в списке
пометка «просрочено». Доступ не режется, сотрудник доучивается.

## 8. Конструктор контента

```mermaid
flowchart TD
    A["HR/admin: создать должность → создаётся пустая траектория (draft)"] --> B["добавить материалы пре-онбординга"]
    B --> C["добавить блоки → уроки → материал + тест с вопросами"]
    C --> D["добавить блок аттестации с финальным тестом"]
    D --> E["нажать: Опубликовать"]
    E --> F{"проверка: у каждого урока есть материал и тест, у теста есть вопросы, есть блок аттестации?"}
    F -->|нет| G["ошибка со списком, что не заполнено"]
    F -->|да| H["траектория active — по ней открывается онбординг"]
    H --> I["правки после публикации достаются только новым сотрудникам: у идущих свой снимок"]
```

## 9. Как ложится на сборку

| Шаг | Что делаем | Диаграммы |
|---|---|---|
| 1 | Каркас: вход (логин/пароль, роли), сущности, БД | 1, 2 |
| 2 | Конструктор: должности, траектория, блоки, уроки, материал+тест, публикация | 2.1, 8 |
| 3 | Найм + пре-онбординг: карточка сотрудника, экран пре-онбординга, отметки просмотра | 3.1, 4, 5 (гейт 1) |
| 4 | Открытие онбординга: кнопка HR «Стажировка пройдена», разворот уроков | 5, 3.1 |
| 5 | Обучение: экран траектории, экран урока, тесты, движок разблокировки | 3.2, 6, 7 |
| — | Всё обучение читается из снимка сотрудника, а не из живого каталога | 2.2, 5, 8 |
| 6 | Аттестация + завершение + пометка просрочки | 7 |

Каждое ветвление на схемах и каждый переход состояний — это тест-кейс. Точные
условия — правила `R-*` и `C-*` в `SPEC.md`.
