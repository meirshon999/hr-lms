# PEG HR LMS — прототип

Рабочий прототип системы онбординга по спецификации из `../SPEC.md`
(машиночитаемый контракт API — `../openapi.yaml`).

Показывает весь путь: **найм → пре-онбординг → стажировка → онбординг (уроки +
тесты) → аттестация → экран-поздравление**, плюс:
- **рабочий конструктор** контента (блоки/уроки/тесты, порядок ↑↓, предпросмотр глазами сотрудника);
- **экран «Обзор»** — сводка по этапам, просрочка, средний срок, воронка по должностям;
- **управление доступом** — сброс пароля, ссылка-приглашение, правка профиля;
- **Swagger UI на `/docs`** — живое дерево API из `../openapi.yaml`;
- **снимок траектории** — правки каталога не ломают тех, кто уже учится;
- **мобильный app-shell** — липкая нижняя кнопка, урок в 2 шага, видеоплеер
  с серверной проверкой просмотра, скелетоны, индикатор офлайна;
- **журнал действий HR** в карточке сотрудника;
- служебная панель **DEMO**: сдвиг даты, журнал **«События»** (переходы состояний
  в реальном времени), сброс демо, встроенный **сценарий**;
- брендинг Pingwin, ~16 демо-сотрудников с разным прогрессом.

## Стек

| | |
|---|---|
| Бэкенд | TypeScript · Fastify · SQLite (`node:sqlite`, без нативных зависимостей) · Zod |
| Фронт | TypeScript · React · Vite · react-router |
| Аутентификация | логин + пароль, подписанный токен (демо) |

Один процесс на бэке, одна БД-файл `server/lms.db`. Структура — модульная, под
перенос в платформу коллеги (см. «Интеграция» ниже).

## Запуск

```bash
cd prototype
npm install        # ставит и server, и web
npm run dev        # поднимает API :3001 и фронт :5173
```

Открыть **http://localhost:5173** (приложение), **http://localhost:3001/docs**
(Swagger UI). При первом старте БД создаётся и заполняется демо-данными.

Нужен Node 20.11+ (проверено на Node 24). Интернета для работы не требует
(шрифты вшиты в сборку); `npm install` — требует.

## Демо-аккаунты

Пароль везде = логин + `123` (например `hr` / `hr123`). Полный список — на экране входа.

| Логин | Роль | Состояние |
|---|---|---|
| `hr`, `admin` | HR / администратор | — |
| `ivan` | сотрудник | только нанят |
| `petr` | сотрудник | пре-онбординг пройден, ждёт кнопку стажировки |
| `olga` | сотрудник | в онбординге, ~4 урока пройдено |
| `sveta` | сотрудник | онбординг завершён |
| `a1…a7`, `k1…k5` | сотрудники | массовка для воронки/аналитики |

## Сценарий демо

Встроен в приложение: экран входа + кнопка **«Сценарий»** внизу. Кратко:

1. `petr` → изучает пре-онбординг, онбординг закрыт.
2. `hr` → карточка «Пётр Захаров» → **«Стажировка пройдена»**.
3. `petr` → «Продолжить» → материал + тест (можно нарочно завалить → пересдать),
   до конца → «Аттестация» → **экран-поздравление**.
4. `hr` → «Конструктор»: порядок ↑↓, «Предпросмотр», «Администратор» (черновик) →
   «Опубликовать» → отказ со списком, чего не хватает.
5. `hr` → «Обзор» (воронка); панель **DEMO** → «+14 дней» → просрочки (тост +
   журнал «События»); Swagger UI на `:3001/docs`.

## Служебное (только прототип, в прод не идёт)

- Панель времени `DEMO` и эндпоинты `POST /api/v1/dev/clock*`, `POST /api/v1/dev/reset`.
- `?t=<token>` в URL — быстрый вход (для скриншотов/тестов).
- `src/seed.ts` — демо-данные. Пересоздать БД: удалить `server/lms.db*`, затем
  `npm run seed` (в `server/`) или просто перезапустить.

## Проверки

```bash
cd server
npx tsx scripts/e2e-check.ts     # сквозной путь сотрудника (нужен запущенный сервер)
npx tsx scripts/e2e-builder.ts   # конструктор: создание, валидация публикации
npx tsx scripts/e2e-snapshot.ts  # снимок: ломаем каталог — учащийся доходит до конца
npx tsx scripts/e2e-guards.ts    # тупики: неполная траектория снимается с публикации, публикация догоняет ждущих
npx tsx scripts/e2e-hr-actions.ts # возврат из архива, продление срока, пауза онбординга
```

HTTP-контракт (все эндпоинты) — `../openapi.yaml` (OpenAPI 3.1). Прототип
реализует его точно; для генерации кода в платформе коллеги давать openapi + SPEC.

## Что упрощено относительно продакшена

- SQLite через `node:sqlite` (experimental-флаг Node) — в проде взять драйвер
  платформы (Postgres и т.п.); слой БД изолирован в `server/src/db.ts`.
- Снимок траектории лежит одним JSON в `employees.snapshot_json`. На больших
  объёмах разумнее вынести в отдельную таблицу — логика чтения вся в `snapshot.ts`.
- Видео — демо-плеер без файла, но прогресс просмотра честно копится на сервере;
  меняется на `<video>` с теми же отчётами о прогрессе.
- Токен — самоподписанный HMAC. В платформе — заменить на её механизм сессий
  (точка входа — `server/src/auth.ts`).
- Файлы (видео/pdf) — заглушки, хранится только `file_url`.
- Нет уведомлений, ролей руководителя, переводов, филиалов — как и в v1-спеке.

## Интеграция в платформу коллеги

- **Модель и правила** — `server/src/domain.ts` (движок разблокировки, гейты,
  аттестация). Это ядро, переносится как есть.
- **Схема БД** — `server/src/db.ts` (`SCHEMA`). Прямой перевод в миграции.
- **HTTP-контракты** — `server/src/routes/*` совпадают со `../SPEC.md` §7.
- **Что заменить платформенным**: `auth.ts` (сессии/JWT), `db.ts` (драйвер),
  хранилище файлов, модуль `routes/dev.ts` (убрать целиком).

## Структура

```
prototype/
  server/
    src/
      index.ts         точка входа Fastify (+ Swagger UI из ../../openapi.yaml)
      db.ts            схема + подключение SQLite
      auth.ts          пароли, токены, проверка ролей
      clock.ts         демо-часы + часовой пояс Asia/Almaty
      snapshot.ts      снимок траектории: снятие и чтение
      audit.ts         журнал действий HR
      events.ts        лог событий для панели (в проде — шина/аудит)
      domain.ts        ЯДРО: гейты, движок уроков, аттестация
      serializers.ts   сборка DTO для API
      seed.ts          демо-данные (~16 сотрудников)
      routes/          auth · me · employees · catalog · analytics · dev
    scripts/           сквозные проверки
  web/
    src/
      api.ts, auth.tsx, lib.tsx
      pages/employee/  ПреОнбординг · Траектория (+ экран-поздравление) · Урок · Аттестация
      pages/hr/        Обзор · Сотрудники · Карточка · Конструктор
      components/      Phone, TestRunner, DevBar, EventLog, DemoScript, Logo, ConstructorPreview, …
```

В проде убрать: `clock.ts`, `events.ts`, `routes/dev.ts`, `/demo/accounts`,
Swagger-регистрацию оставить или заменить.
