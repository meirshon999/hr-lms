# Инструкции для Claude Code

PEG HR LMS — онбординг новых сотрудников сети Pingwin Premium (рестораны,
караоке, боулинг). Код в `app/`: сервер на Fastify + `node:sqlite`, интерфейс
на React + Vite. Один процесс отдаёт и API, и собранный фронт.

**Канон, который нельзя расходиться с кодом:** `SPEC.md` (правила и API),
`LOGIC.md` + `diagrams/` (как это работает), `DESIGN.md` (интерфейс),
`BACKLOG.md` (что сделано и что осталось), `DEPLOY.md` (публикация).
Меняешь поведение — правишь и канон в том же коммите.

## Команды проекта

Корень команд — папка `app/`, не корень репозитория.

```bash
npm install          # ставит зависимости сервера и фронта разом (postinstall)
npm run dev          # сервер :3001 и фронт :5173 одновременно
npm run build        # tsc для сервера + vite build для фронта
npm start            # боевой запуск: один процесс, один порт
npm run seed         # первичное наполнение базы
```

**Проверки — перед каждым коммитом:**

```bash
npm run check        # всё сразу: типы + линтер + сквозные наборы

npm run typecheck    # tsc по серверу, его проверкам и фронту
npm run lint         # eslint; ошибок быть не должно
npm test             # четырнадцать сквозных наборов, сервер поднимается сам
```

`npm test` сам поднимает сервер на свободном порту с базой во временной
папке и гасит его в конце — рабочая база не задевается.

```bash
# отдельный набор, если нужен именно он: сначала живой сервер с LMS_DEV_TOOLS=1
cd app/server
npx tsx scripts/e2e-check.ts       # полный путь сотрудника
npx tsx scripts/e2e-builder.ts     # конструктор и публикация
npx tsx scripts/e2e-guards.ts      # права и запреты
npx tsx scripts/e2e-files.ts       # загрузка файлов
npx tsx scripts/e2e-hr-actions.ts  # действия HR над карточкой
npx tsx scripts/e2e-locations.ts   # точки сети, ИИН, контент по точкам
npx tsx scripts/e2e-snapshot.ts    # заморозка траектории
npx tsx scripts/e2e-ai.ts          # ИИ-конструктор
npx tsx scripts/e2e-users.ts       # роли и служебные аккаунты
npx tsx scripts/e2e-funnel.ts      # воронка по должностям
npx tsx scripts/e2e-plan.ts        # план траектории из документа
npx tsx scripts/e2e-attestation.ts # финальная аттестация
npx tsx scripts/e2e-settings.ts    # настройки ИИ и свой ключ
npx tsx scripts/e2e-claude.ts      # путь Claude на подставном сервере

# передача системы другому владельцу: что осталось от прежнего
cd app && npm run handover           # показать; `-- --yes` — стереть ключ ИИ

# аудит интерфейса: все экраны всех ролей через браузер
cd app && node audit-ui.mjs
```

Адрес сервера наборам задаётся через `LMS_URL`, путь к базе — через `DB_PATH`.
Прогонять на отдельной базе во временной папке, а не поверх рабочей.

## Стиль кода и архитектура

- **Язык.** Строго TypeScript. Избегать `any` и описывать `interface`/`type`
  явно. Исключение одно и осознанное: строки из SQLite и параметры маршрутов
  приходят нетипизированными, там `any` на границе допустим — но дальше границы
  он не идёт.
- **Форматирование.** `async/await` вместо `.then()`. Стрелочные функции для
  компонентов и хелперов.
- **Чистота.** Бизнес-логика отдельно от представления: правила живут в
  `domain.ts`, `snapshot.ts`, `readiness.ts`, `content.ts`, маршруты только
  принимают запрос и отдают ответ. Провайдеры ИИ — за одним слоем
  `ai/provider.ts`.
- **Документирование.** Короткий блочный комментарий над сложной функцией и над
  экспортируемым типом. Комментарии **по-русски** и объясняют **почему** так
  сделано, а не пересказывают код. Комментарий, повторяющий имя функции, — мусор.
- **Ошибки.** Оборачивать в `try/catch` там, где отказ ожидаем: обращение к
  внешнему сервису, загрузка файла, разбор чужого формата. Ответ человеку —
  всегда понятная фраза по-русски через `err(code, message)`; английский текст
  чужого сервиса уходит в журнал сервера, а не на экран HR. Молча глотать
  ошибку нельзя: `catch {}` без объяснения — это спрятанная поломка.
- **Зависимости.** У сервера их восемь. Новая добавляется, только если своими
  силами выйдет заметно хуже, и никогда — нативная. Инструменты разработки
  (eslint, prettier, tsx) в счёт не идут: на боевой сервер они не едут.
- **Линтер.** `eslint.config.mjs` — один на сервер и фронт. Правила ловят
  ошибки, а не вкусы. `any` там оставлен предупреждением: на границе с SQLite
  и параметрами маршрутов он неизбежен, а новое появление всё равно видно.
- **Prettier настроен, но код им не переформатирован — и это осознанно.**
  На этом коде он разворачивает `z.string().min(2).max(40)` в пять строк,
  а `reply.code(400).send(...)` — в три, и раздувает файлы на четверть.
  Конфиг лежит для новых файлов и для того, кто захочет иначе: одна команда
  `npm run format` применит его ко всему. Пока — не применяем.

## Правила проекта

Решения, принятые с заказчиком. Мешает — меняем осознанно и правим этот файл,
а не обходим в коде.

### Продукт

1. **Ничего от ИИ не доходит до сотрудника без подтверждения человека** (C-13).
   По бедному регламенту модель напишет уверенный и неверный тест.
2. **Каркас траектории общий на сеть, содержимое может быть точечным.**
   Отдельные траектории на точку не заводим — контент разъедется.
3. **Траекторию собирают из документов, а не из блоков.** Человек приносит
   регламенты — дерево, уроки с тестами и аттестация строятся сами, и он их
   правит. Обратный порядок («создай блок, потом найди к нему текст») мы уже
   пробовали: на двадцати уроках до конца доходили немногие.
4. **Онбординг открывается только на готовой точке**, и система сама подбирает
   ждущих после каждой правки каталога (C-11). Иначе человек застревает навсегда.
5. **Снимок замораживает обучение** (R-8). Правки каталога не касаются тех,
   кто уже учится.
6. **ИИН — ключ человека по сети.** Телефон не уникален: он меняется.
7. **Права по точкам не делим**, пока не попросят. Точка — свойство данных,
   а не граница доступа.
8. **Кадровик и администратор — разные роли.** HR ведёт людей и содержание;
   аккаунты, состав точек и журнал действий — у администратора. Исключение
   одно: настройки ИИ доступны обоим — платит за ИИ тот, кто им пользуется.
9. **Собеседований в системе нет.** Она начинается со стажёра.

### Инженерные

10. **Один код на боевой и тестовый сервер**, режим решает переменная окружения.
   Отдельная сборка для боя — верный способ поймать ошибку там, где её не
   тестировали.
11. **Провайдеры ИИ за одним слоем** (`ai/provider.ts`), а действующие настройки
    собирает `ai/settings.ts`. Новый провайдер добавляется туда, а не в маршруты.
    Groq и OpenAI обслуживает один код: у них одинаковый формат запроса.
12. **Ключ ИИ задаётся и переменной сервера, и в интерфейсе — кадровиком
    или админом.** Настройка из интерфейса главнее. Ключ **никогда**
    не возвращается наружу — ни в API, ни в журнале: только последние четыре
    знака. В базе он лежит зашифрованным на `TOKEN_SECRET`: продукт переезжает
    копированием файла базы, и открытый ключ уехал бы вместе с копией.
13. **Имена моделей — в настройке, а не в коде.** Проверено: Groq сменил набор
    моделей, и это стоило одной правки настройки вместо переписывания.
    Поэтому же модель — поле в интерфейсе, а не список в коде.
14. **Никаких нативных зависимостей.** Продукт переезжает копированием файла
    базы и запуском.
15. **Секреты не попадают в репозиторий.** В бою сервер не стартует без
    `TOKEN_SECRET`.
16. **Перед коммитом — `npm run check`.** Типы, линтер и все четырнадцать наборов;
    плюс аудит интерфейса, если менялся фронт.

## Чего в проекте нет и не будет

- **Интеграции с iiko или любой другой HRM.** Сотрудников заводит HR вручную.
  Не предлагать синхронизацию ни в каком виде.
- **Уведомлений** (почта, мессенджеры) — решение заказчика, не в этой версии.
- **Стоп-листа по ИИН.** ИИН нужен, чтобы человек не завёлся дважды под
  изменённым именем; отказ в приёме — решение человека, а не системы.

**Папка с финансовыми скриптами iiko в корне репозитория к LMS отношения не
имеет.** Это отдельная задача. Не читать и не править её ради LMS.

## Секреты

Ключи ИИ, пароли и `TOKEN_SECRET` задаются только переменными окружения.
Ключ, присланный в переписке, не коммитить ни в код, ни в примеры, ни в
документацию — в файлах остаются только имена переменных.
