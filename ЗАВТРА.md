Пошагово. Всего ~20 минут, из них 6 — ждать сборку. Делать лучше **сегодня
вечером**, а завтра только открыть ссылку.

которые выполнит Render. Всё, что ниже, — только про твои аккаунты.

## Что получится

Одна ссылка вида `https://peg-hr-lms.onrender.com`, которая открывается с любого
ноутбука и телефона. По ней:

- `/` — приложение (вход `hr` / `hr123`)
- `/docs` — Swagger, живое дерево API

Её же потом отдаёшь коллеге-разработчику.

# Шаг 2. Создать пустой репозиторий — 2 минуты

1. github.com → зелёная кнопка **New** (или github.com/new)
2. **Repository name**: `peg-hr-lms`
3. Выбрать **Private**
4. **Ничего не отмечать** внизу — ни README, ни .gitignore, ни лицензию.
   Репозиторий должен быть пустым, иначе загрузка упрётся в конфликт.
5. **Create repository**
6. Со страницы, которая откроется, скопировать адрес вида
   `https://github.com/ТВОЙ_ЛОГИН/peg-hr-lms.git`

# Шаг 3. Залить проект — 5 минут

Два способа. **Способ А проще**, если не хочется возиться с консолью.

### Способ А — GitHub Desktop (без консоли)

1. Скачать **desktop.github.com**, установить, войти своим аккаунтом GitHub.
2. **File → Add local repository** → указать папку
   `C:\Users\meirb\Downloads\Pingwin DB\iiko api`
   (репозиторий там уже создан, коммиты сделаны — программа это увидит).
3. Сверху появится **Publish repository**. Нажать.
4. Имя `peg-hr-lms`, галочка **Keep this code private** — оставить.
5. **Publish repository**. Через минуту код на GitHub.

Если Desktop скажет, что репозиторий уже связан с другим адресом —
Repository → Repository settings → Remote → вставить адрес из шага 2.

### Способ Б — одна команда

Открыть PowerShell в папке проекта и выполнить, подставив свой адрес:

```powershell
powershell -ExecutionPolicy Bypass -File tools\push-github.ps1 https://github.com/ТВОЙ_ЛОГИН/peg-hr-lms.git
```

Спросит логин и пароль. **Вместо пароля нужен токен**, обычный пароль GitHub не
принимает:

github.com → правый верхний угол → **Settings** → внизу слева **Developer
settings** → **Personal access tokens** → **Tokens (classic)** → **Generate new
token (classic)** → Note: `lms`, Expiration: 30 days, галочка **`repo`** →
**Generate token** → скопировать строку `ghp_...` и вставить вместо пароля.

Токен показывается один раз — скопируй сразу.

**Проверка шага:** открой `https://github.com/ТВОЙ_ЛОГИН/peg-hr-lms` — должны
быть видны папки `prototype`, `diagrams`, файлы `SPEC.md`, `render.yaml`.

# Шаг 4. Развернуть на Render — 5 минут + 6 минут сборка

1. **render.com** → **Get Started** → **GitHub** → разрешить доступ.
   Когда спросит, к каким репозиториям — можно выбрать только `peg-hr-lms`.

2. В панели: **New +** → **Blueprint**.
   Выбрать репозиторий `peg-hr-lms` → **Connect**.
   Render прочитает `render.yaml` и сам подставит все настройки → **Apply**.

3. **Если Blueprint не находится** — делай вручную: **New +** → **Web Service**
   → выбрать `peg-hr-lms` → и заполнить поля ровно так:

   | Поле | Значение |
   |---|---|
   | Name | `peg-hr-lms` |
   | Language | `Node` |
   | Branch | `main` |
   | **Root Directory** | `prototype` |
   | **Build Command** | `npm install && npm run build` |
   | **Start Command** | `npm start` |
   | Instance Type | **Free** |

   Ниже, в **Environment Variables**, добавить три:

   | Ключ | Значение |
   |---|---|
   | `NODE_VERSION` | `24.20.0` |
   | `TZ_LMS` | `Asia/Almaty` |
   | `TOKEN_SECRET` | любая длинная строка, например `pingwin-lms-2026-xKq9` |

4. **Create Web Service**. Пойдёт сборка — 4–6 минут, видно в логе.
   Дождаться зелёного **Live**.

5. Наверху страницы адрес вида `https://peg-hr-lms.onrender.com` — открыть.

**Проверка шага:** открылся экран входа с логотипом Pingwin и списком
демо-аккаунтов.

# Шаг 6. Завтра перед показом — 5 минут

**Главное:** на бесплатном тарифе стенд засыпает после 15 минут простоя,
первое пробуждение ~50 секунд. Поэтому:

1. **За 10 минут до начала** открыть ссылку и дождаться загрузки.
   Дальше он не уснёт, пока им пользуются.
2. Войти как `hr`, нажать **«Сброс демо»** — чистый стенд.
3. Открыть вторую вкладку с этой же ссылкой — в ней будешь показывать
   сотрудника, чтобы не перелогиниваться туда-сюда.
4. Телефон — открыть ссылку и оставить на экране входа.
5. Открыть [DEMO.md](DEMO.md) — сценарий на 5 минут, что нажимать и что говорить.

# Если что-то пойдёт не так

| Проблема | Что делать |
|---|---|
| Ссылка долго грузится | Стенд спал. Подождать минуту, обновить. |
| Render показывает Failed | Открыть Logs, посмотреть последние строки. Чаще всего — не тот Root Directory: должен быть `prototype`. |
| Демо запуталось после кликов | Панель **DEMO** внизу → **«Сброс демо»** |
| Интернет на месте показа лёг | Двойной клик по `START-DEMO.bat` — стенд поднимется локально на `http://localhost:3001` |
| Совсем всё плохо | Скриншоты в `screenshots/` (12 экранов) и `PEG-HR-LMS.pdf` со схемами |

# Полезное потом

- **Ссылка не засыпает** — тариф Starter $7/мес.
- **Обновить стенд после правок** — сделать коммит и запушить; Render
  пересоберётся сам за несколько минут.
- **Отдать коллеге** — дать ссылку на репозиторий GitHub и на живой стенд.
  Что читать первым — `START-HERE.md`.
- **База** сбрасывается при каждом перезапуске: демо всегда чистое. Для боевой
  работы меняется на Postgres, слой изолирован в `prototype/server/src/db.ts`.
