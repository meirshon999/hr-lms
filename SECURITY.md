## Что было найдено и исправлено

Всё перечисленное существовало в версии-прототипе и закрыто до публикации
(коммит `48f978f`).

**Пароли всех учётных записей показывались на экране входа.** Компонент со
списком демо-аккаунтов удалён; список аккаунтов отдаётся только при включённых
демо-инструментах.

**Вход по токену в адресной строке** (`?t=…`). Адрес попадает в историю браузера,
в логи промежуточных серверов и в пересланную ссылку — то есть токен утекал бы
буднично и незаметно. Возможность удалена, остался только вход через форму.

**Служебные адреса `/dev/*` были доступны любому вошедшему**, включая рядового
сотрудника. Среди них полный сброс базы и подмена текущей даты. Теперь они
регистрируются только при `LMS_DEV_TOOLS=1`: на боевом сервере этих адресов
не существует — они не «закрыты правами», а отсутствуют.

**Сервер поднимался с известным секретом подписи токенов**, если переменную
забыли задать. Значение по умолчанию означало бы, что токен любого пользователя
может подделать кто угодно. Теперь в боевом режиме сервер **не стартует** без
`TOKEN_SECRET` длиной от 16 символов.

**Пароль подбирался перебором** — ограничения попыток не было. Теперь 10 неудач
с одного адреса за 15 минут, дальше отказ.

**CORS был открыт любому источнику.** В боевом режиме разрешён только свой домен
(`LMS_ORIGINS`), по умолчанию — тот же, откуда отдан интерфейс.

**HR знал пароли всех сотрудников.** Теперь выдаётся временный пароль, и до его
смены сотруднику доступен только экран смены пароля.

## Что человек обязан сделать руками

1. **Задать `TOKEN_SECRET`** в настройках сервера: `openssl rand -hex 32`.
   Не задан — сервер не запустится, и это правильно.
2. **Сменить пароль администратора** при первом входе. Пароль генерируется при
   первой сборке базы и печатается в лог сервера **один раз**.
3. **Не включать `LMS_DEV_TOOLS` на боевом сервере.** Эта переменная открывает
   сброс базы и список аккаунтов с паролями.
4. **Настроить резервные копии базы.** Файл базы (`DB_PATH`) — единственное место,
   где живут сотрудники, прогресс и контент. Пропал файл — пропало всё.
5. **Убедиться, что адрес открывается по `https://`.** Без него пароли идут по
   сети открытым текстом.

## Что осталось на потом

- **Хранение персональных данных.** ИИН — персональные данные. Для боевой
  эксплуатации нужны согласие сотрудника на обработку при найме и названный срок
  хранения. Это организационный вопрос, а не технический.
- **Журнал входов.** Пишутся действия HR, но не попытки входа. Для расследования
  инцидента этого мало.
- **Двухфакторный вход** для администратора — не сделан, для текущего масштаба
  избыточен.
