# PEG HR LMS — папка для того, кто берёт проект в руки

Прочитать целиком — пятнадцать минут. После этого можно запускать и править.

---

## 1. Что это

Система онбординга новых сотрудников сети **Pingwin Premium** (рестораны,
боулинг, караоке, Астана). Один путь новичка от найма до «онбординг завершён»:

```
приняли → пре-онбординг (читает дома)
        → HR отмечает стажировку пройденной
        → онбординг: блоки → уроки (материал + тест)
        → финальная аттестация → завершил
```

Два интерфейса в одном приложении:

- **Сотрудник** — телефон. Смотрит материалы, проходит тесты.
- **Кадровик и администратор** — компьютер. Заводят людей, ведут карточки,
  собирают содержание в конструкторе.

---

## 2. Как запустить за пять минут

Нужен Node 22.13 или новее. Больше ничего — ни базы данных, ни докера.

```bash
cd app
npm install          # ставит зависимости сервера и фронта разом
npm run seed         # наполняет базу демо-данными, печатает пароли входа
npm run dev          # сервер :3001 и фронт :5173
```

Открыть `http://localhost:5173`. На экране входа есть демо-аккаунты — нажать
и войти. Боевой запуск — один процесс на одном порту:

```bash
npm run build && npm start
```

**Проверки перед каждым коммитом:**

```bash
npm run check        # типы + линтер + четырнадцать сквозных наборов
node audit-ui.mjs    # аудит интерфейса через браузер, если менялся фронт
```

`npm run check` поднимает сервер сам, на отдельной базе во временной папке.
Рабочую базу не трогает.

## 3. Где что лежит

```
app/server/src/
  index.ts        точка входа, регистрация маршрутов
  db.ts           схема и миграции (node:sqlite, без ORM)
  domain.ts       правила: что можно засчитать, когда открыть онбординг
  snapshot.ts     заморозка траектории на момент старта обучения
  readiness.ts    что мешает публикации и что мешает точке
  study.ts        сколько времени нужно провести на материале
  funnel.ts       воронка по должностям
  pdf.ts, docx.ts, mp4.ts   свои разборщики форматов, без библиотек
  secretbox.ts    шифрование ключа ИИ в базе
  ai/             всё про ИИ: провайдеры, настройки, промпты, счётчик расхода
  routes/         маршруты; только принимают запрос и отдают ответ
  scripts/        сквозные наборы (e2e-*.ts) и служебные команды

app/web/src/
  pages/hr/       экраны кабинета
  pages/employee/ экраны сотрудника
  components/     общие части интерфейса
  styles.css      вся палитра и вся вёрстка одним файлом
```

**Канон, с которым код не должен расходиться:**

| Файл | О чём |
|---|---|
| `SPEC.md` | правила и весь API |
| `LOGIC.md` + `diagrams/` | как это работает, картинками |
| `DESIGN.md` | экраны, тексты, цвета, шрифты |
| `BACKLOG.md` | что сделано, что дальше, чего не делаем |
| `DEPLOY.md` | публикация |
| `CLAUDE.md` | правила проекта и команды |

Меняете поведение — правьте канон в том же коммите. Это не бюрократия:
проект переживёт несколько рук, и расхождение кода с описанием дороже.

## 4. Десять решений, которые лучше не ломать

Каждое принято с заказчиком и стоило обсуждения. Полный список —
в `CLAUDE.md`, здесь те, о которые спотыкаются первыми.

1. **Ничего от ИИ не доходит до сотрудника без подтверждения человека.**
   По бедному регламенту модель напишет уверенный и неверный тест.
2. **Траекторию собирают из документов, а не из блоков.** Человек приносит
   регламенты — дерево строится само, он правит. Обратный порядок пробовали:
   на двадцати уроках до конца доходили немногие.
3. **Время на материале считает сервер, а не браузер.** Доказать, что человек
   прочитал, нельзя — можно сделать пролистывание таким же долгим, как чтение.
   Всё, что присылает клиент, режется по часам сервера.
4. **Каркас траектории общий на сеть, содержимое может быть точечным.**
   Отдельных траекторий на точку нет — контент разъедется.
5. **Снимок замораживает обучение.** Правки каталога не касаются тех, кто уже
   учится.
6. **ИИН — ключ человека по сети.** Телефон не уникален, он меняется.
7. **Ключ ИИ вводит владелец системы**, а не разработчик. В базе он лежит
   зашифрованным на `TOKEN_SECRET`, наружу не отдаётся никогда — только
   последние четыре знака. `npm run handover` стирает его при передаче.
8. **Никаких нативных зависимостей.** У сервера их восемь. Продукт переезжает
   копированием файла базы и запуском.
9. **Интеграций с iiko или другой HRM нет и не будет.** Сотрудников заводит
   кадровик вручную. Это решение заказчика, не упущение.
10. **Уведомлений (почта, мессенджеры) в этой версии нет.** Их заменяют цифра
    в боковом меню и виджет «Требуют внимания» на «Обзоре».

## 5. Чего ждать от ИИ-части

ИИ не обязателен: без ключа система работает целиком, только уроки заполняют
руками. Ключ вводит кадровик или администратор в «Настройках» — свой, не
разработчика. Провайдеры за одним слоем (`ai/provider.ts`), имена моделей —
в настройке, а не в коде: провайдеры их меняют.

Три кнопки, и нижняя нужна редко:

- **«Собрать из документов»** — принесли регламенты, получили дерево целиком.
- **«Заполнить блок»** — собирает все пустые уроки блока разом.
- **«Собрать этот урок»** — поодиночке, из панели свойств.

Когда траекторию собирали из документов, сервер запомнил, какой кусок
регламента к какому уроку относится, — поэтому пакетная сборка ничего
не спрашивает. У урока, заведённого руками, куска нет: система спросит
документ на все такие уроки сразу.

## 6. Что осталось

Полный список — в `BACKLOG.md`. Коротко:

- Наполнить содержание. Каркас есть, уроки пустые — пока их не заполнят,
  система работает вхолостую. Это не код.
- Настоящий список должностей от кадровой службы.
- Резервные копии базы. Файл базы — единственное место, где живут сотрудники,
  прогресс и содержание.
- Логотип: положить файл в `app/web/public/logo.svg`, он подхватится сам.
  Пока рисуется запасной пингвин.

## 7. О чём спросить заказчика в первый день

Эти вопросы всплывают всегда, и лучше задать их до того, как что-то написано.

1. Сколько людей нанимаете в месяц и на сколько точек? От этого зависит,
   хватит ли одного сервера и файла базы.
2. Кто вводит ключ ИИ и кто за него платит? Если никто — система работает
   без ИИ, но кадровику придётся писать уроки руками.
3. Нужны ли уведомления? Сейчас их нет сознательно; если понадобятся,
   это отдельная работа и отдельный внешний сервис.
4. Кто отвечает за резервные копии базы и куда они складываются?
5. Останутся ли точки только в Астане? Точки заводятся как обычные записи,
   но сроки и содержание у регионов могут разойтись.

---

## 8. Чего делать не стоит

- **Не подключать iiko или другую HRM.** Решение заказчика, обсуждалось.
- **Не выносить отдельную сборку для боевого сервера.** Один код, режим
  решает переменная окружения, — иначе ошибка вылезет там, где её не
  тестировали.
- **Не класть секреты в репозиторий.** В боевом режиме сервер не стартует
  без `TOKEN_SECRET`.
- **Не заводить нативные зависимости.** Переезд перестанет быть копированием
  файла.
- **Не применять prettier ко всему коду разом.** Конфиг лежит для новых
  файлов; на этом коде он раздувает файлы на четверть. Решение осознанное,
  причина описана в `CLAUDE.md`.
