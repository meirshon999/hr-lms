# PEG HR LMS — онбординг сотрудников Pingwin Premium

Система обучения новичков сети: три точки, разное наполнение онбординга, ИИН как
ключ человека. Здесь и описание того, **как система работает**, и **сам код**.

## Запуск

**Разработка** — `cd app && npm install && npm run dev` → http://localhost:5173,
дерево API — http://localhost:3001/docs

**Боевой сервер** — `cd app && npm install && npm run build && npm start`.
Один процесс отдаёт и API, и собранный интерфейс на одном порту.

## Что нужно задать на боевом сервере

| Переменная | Обязательна | Смысл |
|---|---|---|
| `NODE_ENV=production` | да | боевой режим |
| `TOKEN_SECRET` | **да** | подпись токенов, ≥16 символов: `openssl rand -hex 32`. Без неё сервер **не стартует** — и это правильно |
| `DB_PATH` | нет | файл базы; кладите на постоянный диск, а не во временную папку |
| `UPLOAD_DIR` | нет | куда складывать загруженные видео и PDF |
| `LMS_ORIGINS` | нет | домены, которым разрешено обращаться из браузера |
| `LMS_ADMIN_PASSWORD` | нет | пароль первого администратора; не задан — сгенерируется и напечатается в лог один раз |
| `TZ_LMS` | нет | часовой пояс, по умолчанию `Asia/Almaty` |
| `LMS_AI_PROVIDER` | нет | `off` / `groq` / `anthropic` — см. ниже |

При первом запуске с пустой базой создаются три точки сети, образец траектории
официанта (каркас без содержимого) и один администратор. Дальше HR заполняет
содержимое и заводит людей сам.

## ИИ-конструктор

HR вставляет регламент — модель возвращает черновик урока с тестом, HR правит
и подтверждает. **Без подтверждения человека в каталог не попадает ничего**:
по бедному исходнику модель напишет уверенный и неверный тест.

Провайдер переключается одной переменной, потому что переход «бесплатно → платно»
не должен означать правку кода:

```bash
# бесплатно, для разработки и показа — достаточно одного ключа
GROQ_API_KEY=gsk_...
GROQ_MODEL=openai/gpt-oss-120b   # набор моделей у Groq меняется, держим в переменной

# платно, когда нужно качество и никаких лимитов
ANTHROPIC_API_KEY=sk-ant-...
```

Провайдер выводится из того, какой ключ задан, — отдельно называть его не нужно.
Назвать можно (`LMS_AI_PROVIDER=groq` или `anthropic`), если заданы оба ключа
и надо выбрать. `LMS_AI_PROVIDER=off` выключает всегда.

**Как убедиться, что ключ подхватился.** В журнале запуска сервера есть строка
`ИИ: groq / openai/gpt-oss-120b, речь: groq` — или `ИИ выключен` с причиной.
То же самое отдаёт `GET /api/v1/ai/status`. Лишние пробелы и перевод строки на
конце ключа снимаются сами: ключ почти всегда попадает в настройки вставкой.

Ключа нет — функции нет: кнопки не появляются, адреса отвечают 503 с внятной
причиной. Сейчас на вход принимается вставленный текст; чтение PDF и картинок
умеет только Claude и будет отдельным шагом.

**Диктовка голосом.** Кнопка «Надиктовать» рядом с полем исходника: HR
рассказывает вслух, текст добавляется туда же. Расшифровка идёт через Whisper
на том же бесплатном ключе Groq и включается сама, если ключ задан.

Провайдер расшифровки намеренно отдельный от того, что собирает уроки
(`LMS_STT_PROVIDER`): у Claude входа для звука нет вовсе, и переход на него ради
качества уроков не должен молча ломать микрофон.

## Тестовый сервер

Тот же самый код, плюс одна переменная: **`LMS_DEV_TOOLS=1`**.

Она включает демо-данные при первом запуске, подмену даты, сброс базы и список
аккаунтов с паролями на экране входа. **На боевом сервере этих адресов не
существует** — они не «закрыты правами», а не зарегистрированы вовсе. Держать
два разных кода для боя и теста — верный способ поймать ошибку именно в бою,
поэтому код один, а различает их переменная.

## Проверка

```
cd app/server
npx tsx scripts/e2e-locations.ts     # точки, ИИН, содержимое по точкам, перевод
npx tsx scripts/e2e-guards.ts        # защита от тупиков в онбординге
npx tsx scripts/e2e-snapshot.ts      # изоляция снимком от правок каталога
npx tsx scripts/e2e-check.ts         # сквозной путь сотрудника
npx tsx scripts/e2e-hr-actions.ts    # действия HR над карточкой
npx tsx scripts/e2e-builder.ts       # конструктор контента
npx tsx scripts/e2e-files.ts         # загрузка материалов
npx tsx scripts/e2e-ai.ts            # ИИ-конструктор: слоты, применение черновика
cd .. && node audit-ui.mjs           # все экраны всех ролей в реальном браузере
```

Скриптам нужен живой сервер с `LMS_DEV_TOOLS=1`; адрес задаётся `LMS_URL`.

## Что система делает

Путь новичка: `стажёр → онбординг → завершил → архив`. Онбординг открывается,
когда пройден пре-онбординг **и** HR отметил стажировку пройденной.

Ключевые решения, без которых система ломается:

- **Снимок траектории.** При открытии онбординга структура замораживается за
  сотрудником, поэтому правки каталога не могут сломать того, кто уже учится.
- **Каркас общий, содержимое точечное.** Блоки и уроки одни на сеть, а материал
  и тест урока могут быть свои у каждой точки — кухня и расположение внутри
  здания везде разные.
- **Онбординг открывается только на готовой точке.** Не заполнила свои уроки —
  стажёр ждёт, а не упирается в пустой урок. Заполнила — уходит учиться сам,
  без действий HR.
- **ИИН — ключ человека по всей сети.** Имя можно записать иначе, номер один и
  тот же. Телефон уникальным не является: он меняется.

Подробности и остальные правила — `SPEC.md` §5–6.
