# Публикация

## Стенд для оценки (Render, бесплатно)

**Что это.** Ссылка, чтобы посмотреть систему в работе и показать людям.
**Не боевой сервер** — см. предупреждения ниже.

**Как выложить первый раз**

1. [render.com](https://render.com) → войти через GitHub.
2. **New +** → **Blueprint**.
3. Выбрать репозиторий `meirshon999/hr-lms`. Если его нет в списке — рядом со
   списком есть ссылка настроить доступ Render к репозиториям, надо разрешить.
4. Render сам прочитает `render.yaml` и покажет сервис `peg-hr-lms` → **Apply**.
5. Первая сборка идёт 4–6 минут. Адрес появится вида
   `https://peg-hr-lms.onrender.com`.

**Как обновить после правок.** Ничего не нажимать: `git push` — и Render
пересобирается сам за 3–5 минут.

**Вход на стенде.** Заведите в **Environment** две переменные — `LMS_ADMIN_PASSWORD`
и `LMS_HR_PASSWORD`. Тогда после каждой пересборки входы `admin` и `hr` будут
с вашими паролями. Не задать их можно, но тогда пароли каждый раз новые
и случайные, и подсматривать их придётся в **Logs**.

**Как включить ИИ-конструктор**

Двумя путями на выбор.

**Через интерфейс — проще и без доступа к Render.** Войти кадровиком или
администратором → **Настройки** → выбрать провайдера → вставить ключ →
**Проверить ключ**. Там же написано, где ключ взять. Работает сразу, сервер
перезапускать не нужно.

**Через переменную сервера — надёжнее для боя.** Сервис → **Environment** →
**Add environment variable** → имя `GROQ_API_KEY`, значение — ключ
с [console.groq.com](https://console.groq.com) → **Save changes**. Render
пересоберётся сам, через 3–5 минут в уроках появится кнопка «Собрать ИИ».
Проверить: **Logs** сервиса, строка `ИИ: groq / ...`.

Больше ничего добавлять не надо: провайдер выводится из ключа, модель задана
в `render.yaml`. Ключ из интерфейса главнее серверного, если заданы оба.

> **Ключ из интерфейса шифруется на `TOKEN_SECRET`.** Сменили `TOKEN_SECRET` —
> сохранённый ключ перестанет читаться, и система об этом скажет. Это защита,
> а не поломка: копия базы, увезённая на другой сервер, ключа не выдаёт.

> **Почему ключ может пропасть.** Сервис создан из Blueprint, и Render считает
> хозяином настроек `render.yaml`: переменную, добавленную только руками,
> очередная синхронизация удаляет. Поэтому `GROQ_API_KEY` объявлен в `render.yaml`
> как `sync: false` — «значение задаётся в панели, но переменная моя». Так
> введённый ключ переживает следующий `git push`.

**Что нужно знать про бесплатный план**

- **База и загруженные файлы стираются при перезапуске.** Заполнять уроки на этом
  стенде бессмысленно — пропадут. Он для «посмотреть», а не «работать».
- **Засыпает после 15 минут простоя**, просыпается ~50 секунд. Перед показом
  откройте ссылку за 10 минут, чтобы стенд проснулся.
- **Демо-инструментов на стенде нет.** Ни списка паролей на экране входа,
  ни кнопки сброса, ни выдуманных сотрудников: `LMS_DEV_TOOLS` не задан.
  Это та же система, что пойдёт на ваш сервер.
- Данные всё равно стираются, поэтому **настоящие данные сотрудников сюда
  вводить не нужно** — не из-за дырок, а потому что они пропадут.

Стоимость: **0 ₸**. Постоянный диск и отсутствие засыпания — тариф Starter, ~$7/мес.

## Боевой сервер (ваш)

Отличается от стенда тремя вещами.

**Переменные окружения**

| Переменная | Значение |
|---|---|
| `NODE_ENV` | `production` |
| `TOKEN_SECRET` | `openssl rand -hex 32` — без неё сервер не запустится |
| `DB_PATH` | путь на **постоянном** диске, не во временной папке |
| `UPLOAD_DIR` | путь на постоянном диске для видео и PDF |
| `LMS_ORIGINS` | `https://ваш-домен` |
| `LMS_ADMIN_PASSWORD`, `LMS_HR_PASSWORD` | пароли администратора и кадровика |
| `LMS_DEV_TOOLS` | **не задавать** |

**Запуск.** Либо `cd app && npm install && npm run build && npm start`, либо
контейнером — в корне лежит `Dockerfile`, контекст сборки — корень проекта:

```bash
docker build -t peg-hr-lms .
docker run -d -p 3001:3001 \
  -e NODE_ENV=production \
  -e TOKEN_SECRET="$(openssl rand -hex 32)" \
  -e DB_PATH=/data/lms.db -e UPLOAD_DIR=/data/uploads \
  -v /srv/lms-data:/data \
  --name lms peg-hr-lms
```

**Резервные копии.** Файл базы (`DB_PATH`) — единственное место, где живут
сотрудники, прогресс и контент. Копировать по расписанию; проверить, что копия
разворачивается, а не просто складывается.

## Переезд со стенда на свой сервер

Переписывать нечего. Продукт — один процесс и один файл базы:

1. Остановить сервис.
2. Скопировать файл базы и папку загрузок на новый сервер.
3. Запустить контейнер командой выше, указав те же `DB_PATH` и `UPLOAD_DIR`.
4. Направить домен на новый адрес.

Ни одна возможность Render в коде не используется, поэтому привязки к площадке нет.

## Что проверять после каждой публикации

1. `https://адрес/api/health` отвечает `{"ok":true}`.
2. Главная открывается и это ваш продукт, а не заглушка хостинга.
3. В адресе замочек — `https://`.
4. Вход работает, внутренняя страница открывается по прямой ссылке.
