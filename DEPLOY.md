# Выложить онлайн

Прототип собран в **один сервис**: сервер отдаёт и API, и собранный фронт на
одном порту. Значит его можно поставить куда угодно, где запускается Node.

```
npm install && npm run build && npm start   # в папке prototype/
```
→ всё на `http://localhost:3001` (приложение `/`, Swagger `/docs`).

---

## План на завтра

| | Что | Сколько |
|---|---|---|
| 1 | Залить в приватный GitHub-репозиторий | 10 мин |
| 2 | Render → New Web Service → выбрать репозиторий | 5 мин + 5 мин сборка |
| 3 | Прогреть ссылку за 5 минут до показа | — |
| — | **Запасной вариант** — туннель с ноутбука | 1 мин |

Ссылка вида `https://peg-hr-lms.onrender.com` — её и показывать, и потом
отдавать коллеге.

---

## Шаг 1. GitHub

Репозиторий уже инициализирован, первый коммит сделан. Посторонние файлы
(iiko-выгрузки, `node_modules`, база) исключены `.gitignore`.

1. github.com → **New repository** → имя `peg-hr-lms` → **Private** → Create.
   Ничего не добавлять (ни README, ни .gitignore).
2. Скопировать адрес репозитория и выполнить в папке проекта одну команду:

```powershell
powershell -ExecutionPolicy Bypass -File tools\push-github.ps1 https://github.com/ЛОГИН/peg-hr-lms.git
```

Скрипт сам добавит remote, переименует ветку и отправит. Вручную то же самое:

```bash
git remote add origin https://github.com/<логин>/peg-hr-lms.git
git branch -M main
git push -u origin main
```

Спросит логин и пароль — вместо пароля нужен **токен**: github.com → Settings →
Developer settings → Personal access tokens → Tokens (classic) → Generate new →
галочка `repo` → скопировать и вставить вместо пароля.

Проще без консоли: поставить **GitHub Desktop**, File → Add local repository →
выбрать папку → Publish repository (Private).

## Шаг 2. Render

1. render.com → войти через GitHub → **New +** → **Web Service**.
2. Выбрать репозиторий `peg-hr-lms` → Connect.
3. Render сам подхватит `render.yaml` — проверить, что стоит:
   - Root Directory `prototype`
   - Build `npm install && npm run build`
   - Start `npm start`
   - Instance Type **Free**
4. Create Web Service. Первая сборка ~4–6 минут.
5. Открыть выданный адрес, войти как `hr` / `hr123`.

**Важно про Free-план:** сервис засыпает после 15 минут простоя, первое
пробуждение ~50 секунд. Поэтому **откройте ссылку за 5 минут до показа** —
дальше он не уснёт. Если это неприемлемо — Starter $7/мес, засыпания нет.

**База данных.** SQLite лежит в памяти контейнера: при перезапуске данные
сбрасываются и демо заполняется заново. Для показа это плюс — всегда чистый
стенд. Для боевой эксплуатации меняется на Postgres (слой изолирован в
`prototype/server/src/db.ts`).

## Шаг 3. Запасной вариант — туннель

Если с Render что-то пойдёт не так, публичная ссылка поднимается с ноутбука
за минуту, без регистрации:

```bash
cd prototype && npm run build && npm start          # терминал 1
npx -y cloudflared tunnel --url http://localhost:3001   # терминал 2
```

Во втором терминале появится адрес `https://что-то.trycloudflare.com` — рабочий
с любого устройства, пока ноутбук включён. Держать как страховку.

## Альтернативы Render

| Где | Как | Плюс / минус |
|---|---|---|
| **Railway** | `npx @railway/cli up` из папки проекта | не засыпает, но платно после $5 кредита |
| **Свой VPS** | `docker build -t lms . && docker run -p 80:3001 lms` | `Dockerfile` в корне уже готов |
| **Fly.io** | `fly launch` (подхватит Dockerfile) | бесплатный тариф, чуть больше настройки |

## Переменные окружения

| Имя | По умолчанию | Зачем |
|---|---|---|
| `PORT` | 3001 | хостинг подставляет свой |
| `TOKEN_SECRET` | демо-строка | **обязательно задать свою** на публичном стенде |
| `TZ_LMS` | `Asia/Almaty` | часовой пояс дат и дедлайнов |
| `DB_PATH` | `server/lms.db` | путь к файлу базы |
