# PEG HR LMS v1 — спецификация

Система онбординга новых сотрудников сети Pingwin Premium. Один сервис.
Собрано по требованиям тимлида (интервью 2026-09-07). Логика в схемах — `LOGIC.md`,
экраны и тексты — `DESIGN.md`.

**По этой спецификации собран рабочий прототип — папка `prototype/`** (TypeScript:
Fastify + SQLite на бэке, React + Vite на фронте). Он реализует всё описанное ниже
и служит эталоном поведения. Структура кода — под интеграцию в платформу коллеги.

**Машиночитаемый контракт API — `openapi.yaml`** в корне проекта (OpenAPI 3.1,
все эндпоинты и схемы). Для codegen скармливать его вместе с этим файлом.
В прототипе он же отдаётся живым Swagger UI на `/docs`.

## Область v1

**Только онбординг новичков.** Один новый сотрудник → пре-онбординг → стажировка
(офлайн) → онбординг по траектории должности → финальная аттестация → статус
«завершил».

**Вне v1** (не проектируем): переаттестация действующих, назначение курсов
действующим, биометрия/учёт времени, программа механиков боулинга с кайдзен-
замерами, филиалы, переводы между должностями, повторный приём как отдельная
логика, push-уведомления, массовая загрузка сотрудников списком, отдельные экраны
для руководителя подразделения.

## Договорённости

- Один backend-сервис `lms` + БД. Дробление на микросервисы не делаем.
- Вход: **логин + пароль**. Из сессии/токена берём `user_id` и роль.
- Идентификаторы — UUID. Даты — `YYYY-MM-DD`.
- **Часовой пояс компании — `Asia/Almaty`** (настройка `TZ`). Все «сегодня»,
  даты выхода и дедлайны считаются в нём, а не в UTC: иначе вечером даты съезжают
  на день.
- **Снимок траектории.** При открытии онбординга структура траектории (блоки →
  уроки → материал + тест + вопросы с ответами) копируется сотруднику. Дальше его
  обучение идёт только по этой копии: правки каталога не могут сломать того, кто
  уже учится, и достаются только новым назначениям. Подробно — R-8.
- Где «⚠️» — решение не подтверждено, см. раздел 11.

## 1. Роли

| Роль | Что делает в v1 |
|---|---|
| **employee** | своя траектория: смотрит материалы, проходит тесты. Только своё. |
| **hr** | заводит сотрудников, ведёт их карточки, отмечает стажировку, архивирует, собирает контент в конструкторе. |
| **admin** | всё, что hr + заведение учёток, справочник должностей, настройки. |
| **manager** | ⚠️ роль есть в модели, в v1 без экранов и прав. |

Учётку сотрудника создаёт hr/admin вручную при найме (логин + стартовый пароль).

## 2. Экраны

**Сотрудник (мобильный):**
1. **Пре-онбординг** — список материалов о компании, отметка «Просмотрено». Виден,
   пока `stage = intern`. Подпись: онбординг откроется после стажировки.
2. **Моя траектория** — список блоков и уроков со статусами, кнопка «Продолжить»
   на первый незакрытый урок, полоса прогресса. Виден при `stage ∈ {onboarding, completed}`.
3. **Урок** — материал (плеер/просмотрщик) + «Отметить пройденным», затем тест
   (вопросы по одному, один вариант ответа) + «Завершить тест» + экран результата.
4. **Аттестация** — тот же экран теста, большой финальный тест.

**HR (компьютер) — «Управление»:**
1. **Обзор** — сводка: сколько на каждом этапе, просрочено, средний срок онбординга,
   воронка прохождения блоков по должностям.
2. **Сотрудники** — таблица: ФИО, должность, этап, прогресс (N из M уроков),
   дедлайн, пометка «просрочено». Кнопка «Добавить сотрудника».
3. **Карточка сотрудника** — этап, прогресс по блокам и урокам, переключатель
   «Стажировка пройдена» / «Не прошёл», кнопка «В архив». Блок «Профиль и доступ»:
   логин, сброс пароля, ссылка-приглашение, правка ФИО/телефона.
4. **Конструктор** — должности → траектория должности → материалы пре-онбординга,
   блоки → уроки (материал + тест), блок аттестации. Порядок элементов ↑↓,
   «Предпросмотр» (как видит сотрудник), переключатель «Опубликовать».

Тексты, состояния (пусто/загрузка/ошибка), цвета, шрифты — в `DESIGN.md`.

## 3. Данные

### Учётные

**User** — всё, что логинится.
- `id`, `login` (uniq), `password_hash`, `role` (enum: employee | hr | admin | manager)
- `employee_id` (uuid, nullable — заполнен, если role=employee)
- `is_active` (bool) — false закрывает вход

### Люди

**Position** (должность)
- `id`, `name`

**Employee**
- `id`, `user_id` (uniq)
- `full_name` (1–160)
- `position_id` → Position
- `phone` (string, uniq среди всех сотрудников включая архивных) — E.164, не меняется
- `start_date` (date) — дата выхода
- `stage` (enum: `intern` | `onboarding` | `completed` | `archived`, default `intern`)
- `internship_passed` (bool, default false) — выставляется кнопкой HR «Стажировка пройдена»
- `pre_onboarding_done` (bool, default false)
- `onboarding_opened_at` (datetime, nullable)
- `onboarding_due_date` (date, nullable) — `onboarding_opened_at + config.onboarding_days`
- `overdue` (bool, default false)
- `completed_at` (datetime, nullable)
- `archived_at` (datetime, nullable)
- `pre_snapshot_json` (text, nullable) — замороженный список id материалов
  пре-онбординга, снимается при найме (R-8)
- `snapshot_json` (text, nullable) — замороженная структура траектории, снимается
  при открытии онбординга (R-8)
- индексы: `phone` uniq, `user_id` uniq, `(position_id, stage)`

### Контент (траектория должности)

**Trajectory** — 1:1 с Position.
- `id`, `position_id` (uniq)
- `status` (enum: `draft` | `active`) — `active` = готова, по ней открывается онбординг

**PreOnboardingItem** — материал этапа пре-онбординга.
- `id`, `trajectory_id`, `order` (int), `title`
- `content_type` (enum: `video` | `pdf` | `text`)
- `file_url` (nullable — для video/pdf), `text_body` (nullable — для text)

**Block**
- `id`, `trajectory_id`, `order` (int), `title`
- `kind` (enum: `regular` | `attestation`) — ровно один `attestation`, он последний

**Lesson** — только в блоках `regular`.
- `id`, `block_id`, `order` (int), `title`

**Material** — 1:1 с Lesson.
- `id`, `lesson_id` (uniq)
- `content_type` (enum: `video` | `pdf` | `text`)
- `file_url` (nullable), `text_body` (nullable)
- `min_watch_pct` (int 0–100, nullable — для video; null = засчитывать по «долистал»)

**Test** — 1:1 с Lesson (обычный урок) ИЛИ 1:1 с Block `attestation` (финальный).
- `id`, `lesson_id` (nullable), `block_id` (nullable) — заполнено ровно одно
- `pass_mark_pct` (int 0–100) — задаёт автор контента в конструкторе

**Question**
- `id`, `test_id`, `order` (int), `text`
- `options` (json: список строк, 2–6)
- `correct_option_index` (int) — наружу сотруднику не отдаётся

### Прогресс

**PreOnboardingView**
- `id`, `employee_id`, `item_id`, `viewed_at` (datetime). Uniq `(employee_id, item_id)`.

**LessonProgress**
- `id`, `employee_id`, `lesson_id` — id урока **из снимка** (внешнего ключа на
  живой каталог нет: урок могли удалить)
- `status` (enum: `locked` | `available` | `passed`)
- `material_done` (bool, default false)
- `video_pct` (int 0–100, default 0) — накопленный просмотр видео, растёт только вверх
- `passed_at` (datetime, nullable)
- Uniq `(employee_id, lesson_id)`. Создаётся пачкой при открытии онбординга.

**TestAttempt** — храним все попытки.
- `id`, `employee_id`, `test_id` (из снимка), `attempt_no` (int)
- `answers` (json: `[{question_id, option_index}]`)
- `score_pct` (int), `passed` (bool)
- `submitted_at` (datetime)

### Аудит

**AuditLog** — постоянный журнал действий HR/админа.
- `id`, `ts`, `actor_login`, `action` (hire | internship_passed | internship_failed |
  archive | edit_profile | reset_password | publish | unpublish),
  `employee_id` (nullable), `detail` (text)
- Индекс по `employee_id`. Показывается в карточке сотрудника («История действий»).

## 4. Жизненный цикл сотрудника

Этапы: `intern → onboarding → completed → archived`. Плюс жёсткое удаление на
проваленной стажировке.

| Переход | Когда | Что делает система |
|---|---|---|
| `[*] → intern` | HR/admin заводит сотрудника (≈ за день до `start_date`) | создаёт User + Employee, роль `employee`, `stage=intern`. Разворачивает `PreOnboardingView`-цели по всем `PreOnboardingItem` траектории. |
| `intern → удалён` | HR в карточке: «Стажировку не прошёл» | удаляет User, Employee и весь его прогресс безвозвратно. |
| `intern → onboarding` | выполнено **всё**: `pre_onboarding_done` = true И `internship_passed` = true И `trajectory.status = active` | `stage=onboarding`, `onboarding_opened_at=now`, `onboarding_due_date=now+14д`. Создаёт `LessonProgress` по всем урокам: первый урок первого `regular`-блока → `available`, остальные → `locked`. |
| `onboarding → completed` | сдан тест блока `attestation` | `stage=completed`, `completed_at=now`. |
| любой активный → `archived` | HR в карточке: «В архив» (⚠️) | `stage=archived`, `archived_at=now`, `user.is_active=false`. Прогресс сохраняется. |

**`internship_passed` становится true**, когда HR нажимает в карточке кнопку
«Стажировка пройдена». Автоматического открытия по дням нет — стажировка офлайн,
её длительность у каждой роли своя, и подтверждает её наставник/HR вручную.
Кнопка «Стажировку не прошёл» — удаляет сотрудника целиком.

**`pre_onboarding_done` становится true**, когда число `PreOnboardingView` у
сотрудника = числу `PreOnboardingItem` в траектории.

Порядок пре-онбординга и стажировки между собой не важен — нужны оба.

## 5. Логика обучения

### R-1. Пре-онбординг
Все `PreOnboardingItem` траектории доступны сотруднику с момента найма. Открытие
элемента (для text — долистал; для video — досмотрел до конца; для pdf — открыл)
создаёт `PreOnboardingView`. Порядок не навязываем.

### R-2. Открытие онбординга
См. раздел 4. Пока онбординг не открыт, экран «Моя траектория» недоступен,
сотрудник видит только пре-онбординг.

### R-3. Прохождение урока
Урок = материал + тест. Урок `passed`, когда `material_done=true` И есть
`TestAttempt` с `passed=true`.
- **Материал засчитан** (`material_done=true`): для `text` — конец текста попал в
  экран; для `pdf` — открыл; для `video` — **сервер** проверяет накопленный
  `LessonProgress.video_pct ≥ min_watch_pct`. Клиент шлёт прогресс просмотра
  (`POST /me/lessons/{id}/video-progress`), решение принимает сервер: иначе
  «просмотр» подделывается одним запросом. Идемпотентно.
- **Тест**: `POST` ответов → сервер считает `score_pct` по верным ответам **из
  снимка** → `passed = score_pct ≥ pass_mark_pct`. Попытки не ограничены. Не сдал —
  проходит заново сразу. Пройденный тест можно перепройти: урок остаётся `passed`,
  новая попытка просто записывается.

### R-4. Разблокировка следующего урока
После того как урок стал `passed`: следующий по `order` урок того же блока →
`available`. Если уроки блока кончились — первый урок следующего `regular`-блока →
`available`. Всё строго по порядку.

### R-5. Финальная аттестация
Блок `attestation` (тест без уроков) становится доступен, когда **все** уроки
всех `regular`-блоков = `passed`. Сдача теста аттестации → `stage=completed`.
Не сдал → проходит заново сразу, без ограничений.

### R-6. Просрочка
Ежедневный джоб: если `stage=onboarding` и `onboarding_due_date < today` →
`overdue=true`. Ничего не блокируется, сотрудник доучивается. Снимать флаг не
нужно (при `completed` он неважен).

### R-7. Один онбординг на сотрудника
У Employee ровно одна траектория (по должности), ровно один набор
`LessonProgress`. Смены должности в v1 нет.

### R-8. Снимок траектории (изоляция от правок каталога)
- При найме замораживается список материалов пре-онбординга
  (`Employee.pre_snapshot_json` — массив id). `pre_onboarding_done` считается
  по нему, а не по текущему каталогу.
- При открытии онбординга (R-2) замораживается вся структура траектории
  (`Employee.snapshot_json`): блоки, уроки, порядок, материалы, тесты, вопросы
  **вместе с верными ответами**. Идентификаторы сохраняются как есть, поэтому
  `LessonProgress` и `TestAttempt` продолжают ссылаться на них.
- Всё обучение (список уроков, разблокировка, содержимое урока, оценка теста,
  аттестация, прогресс в карточке HR и воронка) читается **из снимка**.
- Живьём из каталога не берётся ничего. Удаление урока, теста или вопросов у
  `active`-траектории не влияет на тех, кто уже учится.
- Новые назначения берут актуальную версию каталога.

## 6. Конструктор контента (правила)

- **C-1** У каждой должности ровно одна Trajectory. Создаётся вместе с должностью
  в статусе `draft`.
- **C-2** `draft → active` (переключатель «Опубликовать») запрещён, если: нет
  ни одного `regular`-блока с уроком; у урока нет материала или нет теста; нет
  блока `attestation` с тестом; у теста нет вопросов; у вопроса < 2 вариантов
  или `correct_option_index` вне диапазона.
- **C-3** Пока `trajectory.status = draft`, сотрудники этой должности заводятся,
  но онбординг им не открывается (ждут; см. раздел 4).
- **C-4** Правка `active`-траектории разрешена в любой момент и **никак не
  затрагивает тех, кто уже учится** — у каждого свой снимок (R-8). Правки
  достаются только сотрудникам, у которых онбординг откроется после правки.
  Пересчитывать чужой прогресс не нужно.
- **C-5** Блок `attestation` всегда последний и всегда ровно один.
- **C-6** Загрузка файлов (видео/pdf) — через хранилище (⚠️ им займётся другая
  команда; здесь только `file_url`).
- **C-7** Все действия HR/админа над сотрудниками и публикацией пишутся в
  `AuditLog` (кто, что, когда) — см. раздел 3.

## 7. API (сервис `lms`, префикс `/api/v1`)

Формат ошибки: `{ "error": {"code","message","details?"}, "request_id" }`.
Коды: 400 валидация, 401 нет сессии, 403 нет прав, 404, 409 конфликт состояния,
422 бизнес-правило.

### Вход
- `POST /auth/login` — `{login, password}` → `{token, role}`.
- `POST /auth/logout`.
- `GET /me` → `{user, employee?, role}`.

### Сотрудник — обучение
- `GET /me/pre-onboarding` → список `PreOnboardingItem` + отметки просмотра.
- `POST /me/pre-onboarding/{item_id}/view` → отметить просмотренным.
- `GET /me/trajectory` → блоки → уроки со статусами + `progress` (N из M) +
  доступность аттестации. 409, если `stage != onboarding/completed`.
- `GET /me/lessons/{lesson_id}` → материал + тест (вопросы без правильных ответов).
  403, если урок `locked`.
- `POST /me/lessons/{lesson_id}/video-progress` — `{pct}` → накопленный `video_pct`.
- `POST /me/lessons/{lesson_id}/material-done` → `material_done=true` (идемпотентно).
  422 `video_not_watched`, если видео не досмотрено до `min_watch_pct`.
- `POST /me/lessons/{lesson_id}/test` — `{answers:[{question_id, option_index}]}`
  → `{score_pct, passed}`. Пишет `TestAttempt`, при `passed` пересчитывает R-4.
- `GET /me/attestation` → тест аттестации. 403, если R-5 не выполнено.
- `POST /me/attestation/test` — как урок; при `passed` → `stage=completed`.

### HR — сотрудники
- `POST /employees` — `{full_name, position_id, phone, start_date, login, password}`
  → создаёт User+Employee. 422 `no_active_trajectory` в `warnings` (не блокирует).
- `GET /employees?position_id&stage&overdue&search&limit&cursor` → таблица со
  сводкой прогресса.
- `GET /employees/{id}` → карточка: этап, прогресс по блокам/урокам, пре-онбординг, `login`.
- `PATCH /employees/{id}` — `{full_name?, phone?}` (проверка уникальности телефона).
- `POST /employees/{id}/internship-passed` → `internship_passed=true`, пробует
  открыть онбординг.
- `POST /employees/{id}/internship-failed` → удаляет сотрудника целиком. 409,
  если `stage != intern`.
- `POST /employees/{id}/archive` → `stage=archived`, `user.is_active=false`.
- `POST /employees/{id}/reset-password` → `{password}` (новый, показывается один раз).
- `POST /employees/{id}/invite` → `{invite_url, login}`.
- `GET /employees/{id}/audit` → журнал действий по сотруднику.
- `GET /positions`, `POST /positions` — `{name}`; `PATCH /positions/{id}`;
  `DELETE /positions/{id}` (только если нет сотрудников).

### HR — аналитика
- `GET /audit?limit` → общий журнал действий.
- `GET /analytics` → `{by_stage, total, overdue, avg_onboarding_days, funnel:[{position, cohort, attested, blocks:[{title, passed}]}]}`.

### HR — конструктор
- `GET /trajectories/{position_id}` → полное дерево (с правильными ответами) + `problems[]`.
- `POST /trajectories/{position_id}/pre-onboarding` / `PATCH /pre-onboarding/{id}` / `DELETE`.
- `PUT /trajectories/{position_id}/pre-onboarding/order` — `{ids:[...]}`.
- `POST /trajectories/{position_id}/blocks` / `PATCH /blocks/{id}` / `DELETE`.
- `PUT /trajectories/{position_id}/blocks/order` — `{ids:[...]}` (regular; аттестация всегда последняя).
- `POST /blocks/{id}/lessons` / `PATCH /lessons/{id}` / `DELETE`.
- `PUT /blocks/{id}/lessons/order` — `{ids:[...]}`.
- `PUT /lessons/{id}/material` — `{content_type, file_url?, text_body?, min_watch_pct?}`.
- `PUT /lessons/{id}/test` — `{pass_mark_pct}`; `POST /tests/{id}/questions` / `PATCH` / `DELETE`.
- `PUT /blocks/{attestation_id}/test` — тест аттестации.
- `POST /trajectories/{position_id}/publish` — `draft→active`, проверка C-2.
- `POST /trajectories/{position_id}/unpublish` — `active→draft`.

## 8. Настройки

## 11. Решённые ранее вопросы (зафиксировано)

1. **Названия этапов** — рабочие: «Стажировка / Онбординг / Завершил / Архив»
   (`intern/onboarding/completed/archived`). Меняются легко.
2. **Увольнение** — HR жмёт «В архив» в карточке; архивные скрыты в таблице за
   галкой «Показать архивных».
3. **Перепрохождение сданного теста** — урок остаётся `passed` при провальной
   новой попытке (новая попытка просто записывается).
4. **Число вопросов и проходной балл** любого теста и аттестации — задаёт автор
   контента в конструкторе.
5. **Хранилище файлов** — отдельная команда; спецификации достаточно `file_url`.
6. **В конструкторе** работают `hr` и `admin`.

Всё это реализовано в прототипе (`prototype/`).

### Требуют решения (нашлись при сборке прототипа)

- **Повторный приём сейчас невозможен.** `phone` уникален среди всех, включая
  архивных, а повторный приём = новый профиль → уволенного с тем же телефоном
  завести нельзя. Варианты: освобождать телефон при архивации; разрешать дубль,
  если все прежние держатели в архиве; или HR редактирует старую запись.
- ~~Нет журнала действий HR~~ — **сделано**: `AuditLog` + «История действий» в
  карточке сотрудника (раздел 3, правило C-7).
- **Онбординг нельзя поставить на паузу** (болезнь, отпуск) — дедлайн идёт всегда.
- **Список сотрудников грузится целиком** — ок для пилота, для масштаба нужна
  пагинация (`?limit&cursor`).
